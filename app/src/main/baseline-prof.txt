# BBSpace 手工 Baseline Profile
# 覆盖启动 + 首屏 + 进入播放的关键路径。规则以源码/产物中真实存在的类为准；
# 三方库统一使用包级通配（AGP 会解析为运行时命中的方法）。
#
# 规则语法：`<标志位><类描述符>;-><方法名><签名>`
#   HS = hot + startup（预热编译），L 起头是类描述符
#   例：HSPLcom/foo/Bar;->*()V   →  hot+startup，Bar 的全部 void 无参方法
#       Lcom/foo/Bar;            →  仅类（无方法标志）
#
# 目标：让冷启动与首屏滚动路径走 AOT 预编译，减少启动期解释执行。

# ── 自有 Compose 方法的显式规则（P0-1 修正，2026-10-05） ────────────────────────
#
# 为什么需要这一段：上面那些 `HSPL<自有类>;->*()V` 只匹配「无参 void 方法」。
# 实测（expandReleaseArtProfileWildcards 展开产物）：
#   · 展开产物共 56,502 行，其中带 `Composer` 的 3,856 行 —— 全部来自三方库包级通配；
#   · 属于 bbspace 自有类的只有 79 行，且带 `Composer` 签名的 **0 行**；
#   · `HomeScreenKt` / `ThemeKt` / `AppNavHostKt` 在 profile 里各自只有 `-><clinit>()V`。
# 即：首屏 Compose 路径一条都没进 profile，而三方库进了。
#
# 为什么不是把 `->*()V` 改成别的通配：实测 `HSPLcom/naaammme/bbspace/feature/home/**;->*()V`
# 仍然只产出无参 void 方法（0 条 Composer）。所以只能写**显式签名**。
#
# 下面的签名取自 `app/build/intermediates/classes/release/.../dirs` 与各模块
# `bundleLibRuntimeToJarRelease/classes.jar`（javap -p -s），**不是手写的**。
