## 1. 当前阻塞（接手第一优先级）

### 🔴 `:feature:video:compileDebugKotlin` **编译不过**，剩 1 个错误

```
e: PortraitSwipePager.kt:773:162 Return type mismatch:
   expected 'Pair<Long, String?>?', actual 'Pair<Long?, String?>'
```

**位置**：`PortraitSwipePager.kt` 第 773 行，`IOSActionSheetAction(title = "拉黑该 UP 主", ...)`
的 `onClick` 里：

```kotlin
pendingBlockUp = currentEntry?.let { it.ownerMid to it.author }
```

**根因**：`pendingBlockUp` 声明为 `mutableStateOf<Pair<Long, String?>?>(null)`（第 445 行），
而 `currentEntry?.let { ... }` 的接收者是可空的 ⇒ `it.ownerMid` 被推断成 `Long?`。

**修法**（一行，二选一）：
- 改用非空接收者：`currentEntry?.let { e -> e.ownerMid to e.author }` 仍需 `ownerMid` 非空；
- 或显式收窄：`pendingBlockUp = currentEntry?.let { it.ownerMid to it.author }?.let { (m, a) -> m to a }`；
- **最干净**：`pendingBlockUp = currentEntry?.takeIf { it.ownerMid > 0L }?.let { it.ownerMid to it.author }`
  —— `ownerMid` 是 `Long` 非空字段时这条直接成立，且与上方 `if ((currentEntry?.ownerMid ?: 0L) > 0L)` 的判据一致。

> 注意：本行是拆分 `PortraitSwipePager.kt` 时新写的（见 §3.3），原文件里这段逻辑用
> `(currentEntry?.ownerMid ?: 0L).takeIf { it > 0L }?.let { it to currentEntry?.author }`
> —— 那个写法是类型正确的。**照抄原写法即可**。

## 3. 逐条详述

### 3.1 任务 1：OPPO 无缝动画 bug（排行界面最明显）

#### 已确认的根因（**这是本轮最有价值的结论**）

用户猜测"可能是接入全局拖拽反馈所致"—— **猜对了，机制如下**：

OPPO 无缝框架（`com.oplus.animation.OplusViewSeamless`）通过 **`View.getLocationInWindow()` /
`getLocationOnScreen()`** 取锚点矩形来计算过渡几何。而 `appElasticPress` 的形变是
**`Modifier.graphicsLayer`（绘制期变换）**：它改变像素落点，**不改布局**。于是同一个
"锚点现在长在哪"有两个互相矛盾的答案：

| 取法 | 生效相位 | 按压/拖拽形变中返回的值 |
|---|---|---|
| `View.getLocationInWindow()` | 布局期 | **未变形**的旧矩形 |
| `LayoutCoordinates.boundsInWindow()` | 绘制期链（含 layer） | **变形后**的真实矩形 |

用户在**按住卡片（卡片正被放大 ~2% 并被手指拖偏若干像素）**时点开视频，框架按"屏幕上
已经不存在的矩形"起飞 ⇒ 动画从错误的位置/大小开始。**排行页最明显**，因为卡片在瀑布流里、
点击前常带一次未走完的按压回弹。

#### 已落地的修复

**(a) 把真实显示矩形喂给框架** —— 新增 `SeamlessAnchorState.displayRectPx()`：

`core/designsystem/.../seamless/SeamlessCardBridge.kt`
- 新增字段 `layoutCoordinates: LayoutCoordinates?`（**活引用，不是快照**）。
  为什么不能存 `Rect`：`onGloballyPositioned` 只在布局变化时回调，而 `graphicsLayer`
  的缩放平移**不触发布局** ⇒ 存快照会永远拿到未变形值，等于没修。
- 新增 `displayRectPx()`：读 `boundsInWindow()`（含 layer 形变），再用锚点自身
  `getLocationOnScreen - getLocationInWindow` 的差值把**窗口坐标 → 屏幕坐标**。
- `SeamlessAnchor` 用 `Modifier.onGloballyPositioned { state.layoutCoordinates = it }`
  上报；`onRelease` 里置 null（防持有失效节点）。

`core/designsystem/.../seamless/SeamlessVideoCardOpener.kt`
- `tryOpen(...)` 新增 `anchorState: SeamlessAnchorState? = null` 参数；
  `contentRect` 优先级改为 **显式 contentRect > `anchorState.displayRectPx()` > `anchor.screenRect()`**。
  走的是官方 `BUNDLE_RECT`（文档 13772："view 在屏幕上显示的区域，用于框架计算区域错误时兜底"）
  —— 这是**按文档正确使用**，不是绕路。
- `captureCardBitmap(...)` 同样新增 `anchorState` 参数，按显示矩形截屏。
  **参数顺序有坑**：`anchorState` 必须排在 `onCaptured` **之前**，否则尾随 lambda
  （`captureCardBitmap(view) { captured -> ... }`）全部失效。
- 诊断日志改为同时打 `display=` 与 `layout=` 两个矩形 —— 两者不一致就是错位的直接证据。

`core/designsystem/.../seamless/SeamlessVideoCardState.kt`

#### 🔴 一条被证伪的方案（**别再试**）

原本想在 `:ci-lint` 里加 **JUnit 运行时自检**（实例化 `CiIssueRegistry`、断言 `getApi()` 等）。
**在离线依赖集下不可行**，失败链路逐层暴露如下：

1. `testImplementation("…lint-api…")` ⇒ lint-api 的 POM 带 AGP 内部传递依赖
   （`sdklib` / `dvlib` / `ddmlib` / `sdk-common`），**本仓缓存里没有**，Gradle 直接拒绝配置测试类路径。
2. 改成只喂 lint-api 本体 ⇒ `IssueRegistry.<clinit>`（`IssueRegistry.kt:388`）要 Guava 的 `Maps`。
3. 补 Guava ⇒ 还要 kotlin-stdlib 的 `Intrinsics`。
4. 补 kotlin-stdlib ⇒ 还要 `org.jetbrains.uast.UElement`（6 个检测器都 `implements Detector.UastScanner`，
   `ISSUES` 的静态初始化会加载它们）。

**结论：那等于把整个 lint 运行时搬进依赖集。** 这条守卫**只能走源码扫描**（即上面第 5 点）。
`ci-lint/src/test/` 目录已被删除（不要重建），`ci-lint/build.gradle.kts` 已还原为最简形态
（`compileOnly` + `tasks.jar` manifest，无测试配置）。

> 附带结论：官方 `LintTestHarness` 需要 `com.android.tools.lint:lint-tests`，
> **该依赖不在本仓离线缓存里**（`ls $GRADLE_USER_HOME/caches/modules-2/files-2.1/com.android.tools.lint/`
> 只有 lint / lint-api / lint-checks / lint-gradle / lint-model / lint-typedef-remover）。
> 所以"写一段违规代码 → 跑 Lint → 断言报错"这条路**当前也不通**。

## 4. 环境与工具（踩过的坑，别再踩）

### 4.1 构建

- **必须**用 `/d/111j/c/.dsh-tmp/gw.sh`（锁包装器）。直接 `./gradlew` 会与其它 agent 抢锁。
- 日志在 `/d/111j/c/.dsh-tmp/gradle-logs/`，每次只 tail 25 行。
- **死锁**：`gradle.lock/pid` 里的 pid 进程不存在 ⇒ `rm -rf /d/111j/c/.dsh-tmp/gradle.lock`。
  本轮遇到过 1 次（pid=130，进程已死）。
- 一次 `:core:designsystem:testDebugUnitTest` 耗时约 **6m47s**，别设太短的超时。
- **`ops_bash` 调用可能被中断**（本轮多次出现 `Error: tool call aborted`）。
  稳妥做法：`nohup ... > /tmp/xxx.log 2>&1 &` 后台跑，再 `grep` 日志。
  注意 **`pwsh` 里不能直接 `bash script.sh`**（`bash` 不是 cmdlet），必须用 `ops_bash`。

### 4.2 文件编辑

- **改前必须 `read`**（宿主 `read`，不是 `ops_inspect_local_file` —— 后者不产生观察记录，
  之后 `edit` 会报 `file has not been read`）。
- `ops_grep` / `ops_glob` 看过的文件同样**不产生观察记录**。
- 多 agent 并发时，`edit` 常报 **`file changed since it was read`** ⇒ 重新 `read` 再改。
  本轮遇到 3 次。
- 批量改动优先写 Python 脚本（`/d/app/python/python`），
  **必须显式 `encoding="utf-8"`** + `sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")`
  （本机默认 cp936，不写会写成 GBK）。
- **`grep -c` 会把注释行也算进去**。报数字前必须逐条确认是代码还是注释。
  本轮 `SwipeBottomScrimBrush` 数出 3 处，实际**全是注释**（代码 0 处）。

### 4.3 模型路由

- 用户要求"子代理与主代理使用一样的模型"。
- **`spawn_teammate` 不支持指定 model**（schema 里没有该字段）。
- `agent_teams_add_member` 支持 `model` / `provider`，但**团队上限 8 人**，当前已满
  （lead + ui-shell / ui-screens / perf / ui-finish / player / elastic / player2 / elastic2）。
- 实测 `subagent(provider="qoder-cn", model="DeepSeek-Flash")` **被拒**：
  `child LLM route "qoder-cn/DeepSeek-Flash" is not allowed for this Session`。
  `list_subagent_models("qoder-cn")` 只广告 `Qwen3.8-Flash`；但 `~/.dsh/.qoder-catalog.qoder-cn.json`
  里确实有 `DeepSeek-Flash` 条目 ⇒ 拦截发生在**会话级子路由白名单**，不是 catalog。
  **试了 5 次，全部失败，已放弃**。要改只能改宿主配置，不是改代码。
