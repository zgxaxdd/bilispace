## 3. 真机发现的问题（按严重度）

### P0-1（用户所说"严重的 bug"）控制层两套 UI 同时在线

- **现象**：竖屏刷视频时点一下屏幕，会出现**详情页播放器的那套顶栏/底栏**（返回箭头、标题、弹幕开关、旋转图标、⋮、
  暂停键、时间、音轨/画质/倍速/全屏、进度条），**同时** story 那套（UP/标题/话题、右侧点赞/评论/收藏/分享/⋮、横屏胶囊）也还在。
  结果：**两个 ⋮、两套顶部图标、两种"关闭/返回"入口并排**。
- **证据**：`27-tap-once.png`（两套同屏）；`25-more.png`（story chrome 自动隐藏后只剩播放器那套，说明两者各自独立计时、互不感知）。
- **代码位置（静态确认，未改）**：
  - `VideoPlayerPane.kt:643 var showCtrl`（pane 自己的控制层，`swipePagingActive` 只用于手势穿透与中央播放键，**不管 chrome 显隐**，见 `:2512` / `:2552`）；
  - story chrome 在 `SwipeSessionChrome.kt` / `PortraitSwipePager.kt`，与 `showCtrl` 无任何联动。
- **根因**：两套 chrome 各自维护"显隐"，没有"当前只有一个控制层可见"的单一判据。
- **修复方向**：把"控制层可见性"提升为会话级唯一状态（例如 `SwipeChromeOwner { Story | Player | None }`），
  点屏幕只切换 owner，不做两套独立计时；`VideoPlayerPane` 在 `swipePagingActive` 时只允许中央播放键，不渲染自己的顶/底栏。
- **验收**：竖屏刷视频任意时刻，屏幕上**最多一套**顶栏、**一个** ⋮、**一个**返回/关闭入口（可写成源码守卫 + 真机截图各一张）。

### P0-2 横屏时顶栏压到状态栏、底栏压到手势条

- **现象**：强制横屏后，顶部标题「抛开剂量谈毒性的五种产品」与系统时间/信号/电量**重叠绘制**；
  底部进度条与三条手势条重叠。整条顶栏没有为 `statusBars` / `navigationBars` 留 inset。
- **证据**：`32-land-chrome.png`、`33-after-rotate.png`（可清楚看到 17:38 / 46% 与标题叠字）。
- **代码位置（静态确认）**：`VideoPlayerPane` 顶栏 `Row` 与底栏控制行未按 `WindowInsets` 加 padding
  （全屏态依赖 activity 的 `enableEdgeToEdge`，但 pane 自己的 chrome 没有消费 inset）。
- **修复方向**：横屏（`isFull` / `landscapeForced`）时顶栏加 `statusBarsPadding` 等价 inset，底栏/进度条加
  `navigationBarsPadding`；竖屏 story 态同样检查（刘海/挖孔机型差异）。
- **验收**：横屏截图里标题与状态栏图标**零像素重叠**；进度条与手势条不重叠（真机截图 + 一条源码守卫钉 inset 消费点）。

### P0-3 强制横屏后**页面内没有可见的「还原/竖屏」入口**

- **现象**：竖屏点「横屏」→ 旋转成功（`mRotation=1`）；但旋转后那个「横屏」胶囊**消失**
  （`PortraitSwipePager.kt` 的 `SwipeLandscapeFab` 条件是 `!isPortraitVideo && !landscapeForced && …`），
  story 互动栏也消失，屏幕上只剩播放器控制条。用户要找"怎么转回去"，只能先点屏幕、再点右上角那颗**小旋转图标**
  （实测：点它 `mRotation=1 → 0`，功能是通的，**但不可见/不可发现**）。
- **证据**：`30-p.png`（竖屏有「横屏」胶囊）→ `32-land-chrome.png`（横屏后无任何"竖屏/还原"字样）。
- **根因**：`landscapeForced` 同时被用作"隐藏入口"的判据 —— 需要"转回去"的时刻恰恰是这个判据为真的时刻。
- **修复方向**：横屏态提供**同位置、同语义反向**的入口（胶囊文案「竖屏」/图标旋转），
  或把 pane 顶栏那颗旋转图标在 story 横屏态放大/加文字；判据拆成"是否显示入口"与"当前方向"两件事。
- **验收**：进入横屏后 3 秒内，用户无需点屏幕即可看到一个明确的「竖屏/还原」入口；点击后 `mRotation` 回到 0 且 story UI 恢复。

### P0-4 横屏态 story 互动栏/信息区整体消失（模式混用）

- **现象**：横屏后点赞/评论/收藏/分享/UP/标题/话题全部不见，只剩播放器控制条；竖屏时它们又在。
  用户感知为"进横屏就变了个 App"。
- **证据**：`32-land-chrome.png` vs `21-p1.png`。
- **修复方向**（与 P0-1 同一根因，一起做）：横屏是**播放器模式**，story 元信息应明确以"播放器 HUD"形态保留（或明确声明横屏不提供互动），
  不能靠"story chrome 的显隐恰好没生效"来实现。
- **验收**：横屏态有明确的设计结论（保留哪些入口）并写进注释；截图与结论一致。

### P1-1 某页全黑约 20 秒（待复现）

- **现象**：一次翻到某页后，画面全黑、story 元信息正常、点赞/收藏显示「待确认」，持续 ≥20s。
- **证据**：`17-story-now.png`；同一时段的 `PlayWatch` 是 `rendered=0 skipped=60~61 net=442532`（**有流量、在跳帧、不出画**）。
- **可能性**：① 该视频本身黑场开场（未能证伪）；② 新页 surface 未 attach / 被旧页 surface 抢走；③ 解码器首帧超时。
- **下一步（本轮未做）**：在同一视频上重复 3 次进入，若稳定复现 → 按 ② 查 `VideoPlayerPane` 的 `PlayerView` attach/release 时序；
  若不能复现 → 记录为"疑似黑场视频"，不再追。
- **验收**：连续 10 次翻页，任意页 `hasRenderedFirstFrame` 在 3s 内为真；`PlayWatch` 不出现连续 3 个窗口 `rendered=0 && skipped>0`。

### P1-2 退出页面后播放器仍在解码（隐藏 surface 空转）

- **现象**：BACK 关闭详情页回到首页后，日志仍在打 `PlayWatch rendered=0 skipped=60 net=442532`（小横条在播，但帧被 skip）。
- **位置**：小横条（`LinkedBottomDock` / `CapsuleIndicator`）确实在播，属预期；但"rendered=0 + skipped=60"说明**画面没被消费却仍在解码**，
  在长时刷视频/待机下是白耗电与发热源。
- **修复方向**：小横条不可见/被遮挡时把播放器降级为"只出音频"或暂停解码（`setVideoSurface(null)` / 降 surface 帧率）。
- **验收**：首页停留 60s，`PlayWatch` 的 `skipped` 不再持续增长（或 `rendered` 与 `skipped` 同步归零）。

### P2 顶栏/底栏的具体优化点（用户提到"顶栏和底栏有部分需要优化"）

1. **重复入口**：story 右侧 ⋮ 与 pane 右上 ⋮ 同屏（`27-tap-once.png`）—— 合并为一个"更多"，且位置固定。
2. **两套图标语义不一致**：pane 顶栏是「返回 / 弹幕 / 旋转 / ⋮」，story 是「点赞/评论/收藏/分享/⋮/横屏」，用户要记两套。
3. **横屏胶囊位置跟画幅走**：`PortraitSwipePager.kt:746-766` 按 `imageBottomPx + sm` 定位，竖屏视频直接隐藏；
   结果是同一手势在不同视频上"有时有、有时没有"。建议固定位置（右下/右上角锚点）并统一显隐判据。
4. **底栏信息区留白**：`21-p1.png` 中标题/话题下方的黑色空白占比偏大（信息区与画面下沿脱节），
   建议按画面下沿锚定、或把话题行收进标题下方一行。
5. **状态栏图标颜色**：横屏/深色视频上 `isAppearanceLightStatusBars` 需要跟随内容亮度（`VideoScreen.kt:481` 已有逻辑，横屏分支需复核）。

## 4. 优化任务书（分批，含验收判据）

> 原则：**先收口"两套 UI"，再修 insets，再谈视觉**。P0-1/P0-3/P0-4 是同一根因的三张面孔，一起改；P0-2 独立且低风险。

### 批次 A（P0-1 + P0-4）：控制层唯一化

- **范围**：`PortraitSwipePager.kt`、`SwipeSessionChrome.kt`、`VideoPlayerPane.kt`（`swipePagingActive` 分支）
- **做法**：引入会话级 `SwipeChromeOwner`（Story / Player / None）+ 单一点击切换；pane 在 story 态不渲染自绘顶/底栏。
- **验收**：
  1. 真机截图：竖屏任意时刻最多一套顶栏、一个 ⋮；
  2. 源码守卫：`SwipeSessionChrome` 与 pane chrome 不得同时被 `visible=true` 组合出来（可用现有"源码扫描 + 单判据"范式）；
  3. `PlaybackPageModeTest` 增加"owner 迁移"纯函数测试（Story↔Player↔None 三态闭环）。

### 批次 B（P0-2）：安全区 insets

- **范围**：`VideoPlayerPane` 顶栏/底栏/进度条；`SwipeSessionChrome` 顶/底
- **做法**：横屏与全屏统一消费 `statusBars` / `navigationBars` / `displayCutout` inset，禁止硬编码 padding。
- **验收**：横屏截图标题与状态栏零重叠；源码守卫钉住 inset 消费点；竖屏挖孔机型复核一张截图。

### 批次 C（P0-3）：还原入口

- **范围**：`SwipeLandscapeFab`（`SwipeSessionLeaves.kt`）+ 调用点判据
- **做法**：拆"是否显示"与"当前方向"；横屏态显示「竖屏」反向入口，位置与「横屏」一致。
- **验收**：横屏后 3s 内可见反向入口；点击 `mRotation` 回 0；真机截图两张（横屏入口 / 点击后恢复）。

### 批次 D（P1-1 + P1-2）：首帧与空转

- **做法**：复现优先；若复现，查 `PlayerView` attach/release 与 `surfacePowersave` 分支；小横条隐藏时降级为音频或暂停解码。
- **验收**：连续 10 次翻页 3s 内出帧；首页停留 60s `skipped` 不再单调增长。

### 批次 E（P2）：顶栏/底栏视觉与信息层级

- **做法**：合并重复入口、统一图标语义、横屏胶囊固定锚点、收窄底栏留白、话题行并入标题块。
- **验收**：`27-tap-once.png` 类状态不再出现双 ⋮；底栏占比用截图标注量化（信息区高度/画面下沿间距写入注释）。
