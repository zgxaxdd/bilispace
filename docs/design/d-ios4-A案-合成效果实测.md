## 2. A1（双层叠）：为什么否掉

**做法**：渐变保留（末档仍 0.82），控件行再 `background(黑88%)`。

| 位置 | 合成 sRGB（白画面为底） | 白字对比 |
|---|---|---|
| 控件行上沿**外**（渐变 a≈0.767） | 0.2335 | 11.11:1 |
| 控件行上沿**内**（再叠 88%） | 0.0280 | 20.13:1 |
| **两带亮度比** | **1.81:1** | — |

**1.81:1 是什么概念**：WCAG 里 1.5:1 已是「明显可辨的亮度差」。这里在一条**水平直线**上突变 1.81:1，
用户会看到一条「黑条贴上去」的接缝——**这就是 Admin 担心的硬切线，实测存在**。

降级到黑 60% 也不行：两带 1.21:1（仍可见），且行内合成 sRGB 0.053 比渐变暗 3.4 倍，**断层更刺眼**。

## 3. A2（并入渐变）：单层怎么做到「有实底感」而无接缝

**做法**：**不叠第二层**，改渐变末段形状 —— 把 `PlayerOverlayScrimBottomEnd` 从 **0.82 → 0.88**（`:214`，改既有常量的**值**，不是新增字面量），
并在 0.60→1.00 之间加两个中间档让它**平滑收口**到 0.88：

```
原:  0 → .44(.10) → .58(.24) → .68(.44) → .76(.60) → .82(1.0)
新:  0 → .44(.10) → .58(.24) → .68(.44) → .78(.60) → .86(.644) → .88(1.0)
                                                    ↑ 控件行上沿 f=76/118=.644
```

**关键设计**：把 `.644`（控件行上沿的精确比例）设成一个档位 ⇒ 控件行整段落在 0.86~0.88 的**近平台区**，
上沿前后 alpha 只差 0.0015 ⇒ **物理上没有切线**。

| 位置 | alpha | 合成 sRGB | 白字对比 |
|---|---|---|---|
| 进度行中心 y=48（f=.407） | 0.663 | 0.3366 | 7.36:1 |
| 控件行上沿 y=76（f=.644） | 0.860 | 0.1400 | 15.58:1 |
| 控件行中部 y=93（f=.788） | 0.868 | 0.1319 | 15.98:1 |
| 层底 y=118（f=1.0） | 0.880 | 0.1200 | 16.56:1 |
| **上沿内外差** | **Δ=0.0015** | — | **1.00:1（不可见）** ✅ |

## 4. 进度行与控件行之间的「台阶」

A2 下，进度行胶囊底（黑45% 叠渐变）= sRGB 0.1851，控件行底 = 0.1319 ⇒ **两带 1.20:1**。

**判断**：这是**有意的分界**，不是瑕疵 —— 1.20:1 在深色区是「一层薄阴影」的量级，
读作「进度行浮在工具条之上」；且两行之间还有 12dp Spacer（`:2648`）的纯渐变过渡带，
用户看到的不是硬边。**这条我认为可以保留。**

若 Admin 要求抹平：把进度行胶囊从黑45% 降到黑30%，两带比降到 1.06:1，但未播轨对比从 4.58 掉到 3.55（仍 ≥3:1）。**不推荐**——进度行需要比工具条更「浮」才读得懂是独立控件。

## 5. 进度行：胶囊要不要保留（对比表）

A2 下进度行中心渐变底 sRGB = 0.3366（内嵌）/ 0.3495（全屏）。三种做法：

| 做法 | 胶囊/底 | 未播轨（白50%） | 已播轨/滑块（白100%） | 判 |
|---|---|---|---|---|
| **保留胶囊黑45%（推荐）** | 0.1851 | **4.58:1** ✅ | **13.35:1** ✅ | 两档都达标，不需要任何豁免 |
| 保留胶囊但改黑60% | 0.1346 | 5.01:1 ✅ | 16.4:1 ✅ | 更暗，但胶囊与控件行几乎同色 ⇒ 进度行「浮」不起来 |
| **去掉胶囊**（方向一） | 0.3366 | 白50% → **3.18:1** ⚠️ 刚过线；白45% → 2.88:1 ❌ | 13.6:1 | 需要把未播轨提到白50% 才达标，**且要 Admin 认「未播轨非文本 3:1 刚好卡线」** |

⇒ **A2 保留胶囊黑45%**：未播轨只需从现状白42% 提到 **白50%**（`:291` 改值），4.58:1 一次达标，
不需要豁免论证、不需要改测试口径。

## 7. 风险与未验证

- **未上真机**：所有数字是 WCAG 公式算的，**观感未验证**；0.88 是否让底部「太重」只有截图能判。
- **❗停靠点必须写「具名符号」，绝不写内联 `Color.Black.copy(...)`**（核查员 2026-10-17 13:0x 实测的假绿陷阱，**本文旧版此处写的是错的**）
  `PlayerOverlayScrimContrastTest.parseStops` 的停靠项正则是**裸标识符**
  （`[A-Za-z][A-Za-z0-9_.]*`，`:82`），且 `:86` **见 `)` 即截断**。
  照字面写成 `0.644f to Color.Black.copy(alpha = 0.86f),` 的后果**不是解析器报错，而是解析在
  那一行截断**：只读到它之前的停靠 ⇒ 其后全被外推成末档平台 ⇒ **墨迹带与所有对比度断言假绿**。
  正确写法（两步）：

  ```kotlin
  private val PlayerOverlayScrimDock = Color.Black.copy(alpha = 0.86f)   // ← 这行是"单行 copy 形态"
  // ...
      0.644f to PlayerOverlayScrimDock,                                // ← 停靠行只写裸符号
  ```

- **⚠️ 本文的基线与对比度表已过时（2026-10-17 13:0x 标注）**：§4~§6 按**旧六档**（末档 0.82、
  存在 `0.44f`/`0.60f` 两档）算的。最终落地是**五档**
  `0 → .44@.10 → .58@.24 → .88@.36 → .88@1`（`VideoPlayerPane.kt:1872-1879`）：
  `Base`/`LowerMid` 两常量已删、**没有 0.644 档**、未播轨保持白 **0.42**（未提到 0.50）。
  现行判据一律以 **`docs/design/d-ios6-方向二-可执行规格-定稿v3.md`** 为准。
- **`4.58:1` 的前提已消失**：该数算的是「轨道 × 进度行黑45%胶囊底」，而 `PlayerProgressDockScrim`
  本批已删。**真机手不得再用「112px 均匀深带」当 10809 的判据**——那条签名应当**消失**。
  现行未播轨判据是「无胶囊底、轨道直接坐在 0.88 实底上，白42% = **4.01:1**（两态相同）」。
- **两态各算一次**：全屏 H=126 时控件行仍在 y=76..110（底部留白变 16），f 值不变 ⇒ **A2 的两态几何天然一致**，这是它比「按比例缩放」的方案更稳的地方。
