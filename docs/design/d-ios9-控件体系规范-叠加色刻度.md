# 控件体系规范 v1 · 白/黑叠加刻度（回答用户那句「不统一」）

> 出品：设计师。2026-10-17 14:0x。**用户口径**：「ui 不够现代化**和统一**」。
> 本文是 `d-ios8-改版规格v4` 的姊妹篇：那篇治**播放页**，本篇治**全站控件体系**。
> 边界：只读、零源码改动。

---

## 0. 诊断：「不统一」的根不是审美，是**体系缺了一层**

本仓已有三套刻度：`BiliSpacing`（间距）、`BiliRadius`（圆角）、`BiliColorRoles`（页面角色色）。
**但没有第四套**——**浮层叠加色（white/black over media）没有任何 token**。

后果（实测 `grep -rhoE "Color\.(White|Black)\.copy\(alpha = 0\.[0-9]+f?\)"` 全仓）：

| 事实 | 数值 |
|---|---|
| 不同的白/黑 alpha 字面量 | **30+ 种** |
| 播放页**一个文件内**的白度档 | **6 种**（1.00/0.90/0.68/0.60/0.42/0.24/0.18/0.16 中的 6 档同时在用） |
| 高频重复但语义相同的值 | `白 0.24`×3、`白 0.16`×2、`白 0.14`×3、`黑 0.30`×2、`黑 0.72`×2 … |

`BiliColorRoles` 的 KDoc（`BiliColorRoles.kt:26-31`）自己写着它管的是
"一级/二级/三级文字 + separator + fill" —— **全部是页面内的角色**。
**浮层（压在视频/图片上的白字与黑底）不在它的射程内**，所以每个文件各自发明 alpha。
**这就是"不统一"的技术根因，不是设计水平问题。**

---

## 1. 刻度设计：白 5 档 + 黑 3 档

**全部按语义命名，不按数值命名**（`BiliColorRoles` 的体例）。
每一档都写清**判据**（什么场合用 / 什么场合不用），这样下一轮不会又长出一档。

### 1.1 白（浮层上的前景 / 浅底上的叠加）

| token | 值 | 语义 | 判据 |
|---|---|---|---|
| `onMediaPrimary` | **1.00** | 浮层**主**前景 | 主操作图标、已播轨、滑块实心 |
| `onMediaSecondary` | **0.92** | 浮层**次要**信息 | 时间文本、副标题。**比 0.90/0.68 归并到此** |
| `onMediaTertiary` | **0.60** | 浮层**可点选项**的常态 | 控件行非当前档。**这是"选项"不是"弱信息"** |
| `overlayPressed` | **0.18** | **按下**叠色（唯一用途） | 按压反馈、药丸描边 |
| `disabled` | **0.24** | **禁用**（唯一用途） | 停用滑块、不可点项 |

⚠️ **`onMediaTertiary`=0.60 与 `disabled`=0.24 刻意不同**：
前者是"可点但非当前"，后者是"不可点"。**混用会让用户以为灰的那档能点**——
这正是我上一条报的语义缺口。

### 1.2 黑（浮层底 / 压暗）

| token | 值 | 语义 | 判据 |
|---|---|---|---|
| `mediaScrimToast` | **0.72** | 短暂**浮层**底（Toast、拖动气泡） | 独立于控件层、直接压在画面上的小块 |
| `mediaScrimDense` | **0.38** | **贴底**小底（药丸/开关底盘） | 压在大面积控件层底之上 |
| （渐变最暗端 0.88 不进刻度） | 0.88 | 播放页控件层**渐变末档** | 它是**渐变的一站**，不是一档叠加色 |

⚠️ **0.88 必须排除在刻度之外**，否则下一轮有人会拿它当"标准浮层底"铺到别处。
它与 `0.72` 的语义差别是**"随内容高度变化的渐变" vs "固定尺寸的小块"**。

### 2.1 弹幕开关必须换语言（用户第五条硬伤）

它现在用 `PlayerPillScrim`(黑0.30) + `PlayerPillBorder`(白0.16) 那套「药丸」——
**药丸是被否掉的形状**。归并后它自动落到 `mediaScrimDense`(黑0.38) + `overlayPressed`(白0.18)
= 与控件行按压反馈同一套。**这就是「统一」的落点，不是重新设计一个样式。**

## 3. 全站推广（第二波，本版不落）

`Button(` 18 处 / `TextButton(` 97 / `IconButton(` 69 / `Card(` 80 / `AlertDialog(` 36 /
`.clickable(` 52 —— **本波一行不动**。理由：

1. **它们大多在页面内**，`BiliColorRoles` 已经管着（`primaryLabel`/`secondaryLabel`/`fill`）；
2. 浮层刻度只在**压在媒体上**的控件才需要，直接全站套会误伤页面内控件；
3. 一次改 97 处 `TextButton` 的风险 ≫ 收益。

⇒ **第一波只做播放页 + 弹幕开关**（约 8 个常量），
**推广到 Dialog / BottomSheet / 浮层按钮留第二波**，届时按同一张表逐类归。

---

## 4. 为什么不给它加 `DesignTokenLintTest` 棘轮

棘轮是**按行计数**的（`DesignTokenLintTest.kt`），而 alpha **不是 dp**、不受棘轮管。
⇒ **要立的新规矩是另一条**：**新增浮层叠加色必须取自 §1 的八档，不得就地写 `Color.X.copy(alpha = …)`。**
这条用**行级 grep 守卫**实现（不是计数棘轮）：

```
禁止：文件内出现 Color.White|Black.copy(alpha = …) 且该值 ∉ {1.0,0.92,0.60,0.18,0.24,0.72,0.38}
```

⚠️ 这是**建议，不是本波交付**——因为它会一次性红掉全仓三十多个现有字面量，
必须与 §3 第二波同批落。**现在写守卫会把树搞红**，我不建议。
