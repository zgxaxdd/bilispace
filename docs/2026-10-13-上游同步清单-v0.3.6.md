## 1. A / B / C 分级

分级口径（与 SX-11 / v0.2.9 轮一致）：
- **A** = 与 bbspace 结构可对应、低风险、可直接移植；
- **B** = 有价值但**需改造**（依赖上游特有结构/依赖/设置项，或落在 bbspace 没有对应物的位置）；
- **C** = 不移植（TV 端、上游独有子系统、基础设施差异、纯版本号/文档）。

## 2. 结论

1. **本区间 A 级 16 组**（v0.2.9 轮为 0 组）。其中 A1/A2 是**与业务无关的基础设施**
   （ASM 字节码补丁、Android Lint 检测器模块），A4~A16 是**自包含的纯逻辑/纯判据**
   （版本提升、拖拽闩锁、几何取法、缓存类、骨架判据、过期判据…）。它们绕过了「bbspace 是重写实现」这个根本障碍。
2. **本区间唯一「会发错请求」的缺陷是 A16**：`TGT:VideoViewModel.kt:1409` 的 `val target = !(state.userState?.liked ?: false)`

## 4. 落地要点与风险（供下一轮任务书引用）

1. **A1 的接线差异**：上游的 `build-logic` 是**独立 `includeBuild`**（`BP:settings.gradle.kts:15-16`），
   里面是 `java-gradle-plugin` + `compileOnly("com.android.tools.build:gradle-api:…")` + `implementation("org.ow2.asm:asm:9.8")`
   （`BP:build-logic/build.gradle.kts:9-12`，附有**明确注释**：不要改回 `buildSrc`，`compileOnly` 在 daemon 里会报
   `Unable to load class`，`implementation` 又会泄漏 gradle-api 触发
   `plugin is already on the classpath with an unknown version`）。
   bbspace 的 `build-logic` **已经是 `includeBuild`**（`TGT:settings.gradle.kts:2` 含 `includeBuild("build-logic")`），

   而不是塞进 `:convention`。
