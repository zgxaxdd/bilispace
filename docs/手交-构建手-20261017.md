### 3. 证据快照体系的修复（我自己做的关键修复）

**问题**：全仓 10 个快照目录的 `MANIFEST.md5` 有四类格式缺陷，标准 `md5sum -c` **6/10 全部失败**，等于快照不可自证：
- CRLF 行尾（6 个目录）
- BSD 风格 `*` 前缀（4 个）
- `./` 相对路径前缀
- 只覆盖 `TEST-*.xml`、漏掉 `BUILD.txt` 与运行日志

**根因**：MSYS 的 GNU coreutils `md5sum` 检测到"可能是二进制"会自动加 `*`。

**修复后**：10/10 目录全部 PASS，且我两处新快照（ds 34/34、video 15/15）都当场跑过 `md5sum -c`。

**立下的正确写法（W64）**：
```bash
cd <快照目录> && md5sum -t BUILD.txt *.xml *.log > MANIFEST.md5
md5sum -c MANIFEST.md5     # 必须当场跑并贴输出，不跑不算快照完成
```
⚠️ **必须带 `-t`**，否则又会生成 `*`。

## 三、纪律与教训（下一位接手必须知道）

### 3.1 Gradle 操作铁律

1. **`--rerun` 只在单任务命令行生效**，多任务并列会被静默丢弃 ⇒ **一个任务一次调用**。
2. **同一时刻只允许一个 Gradle 调用**。判据：按**顶层 `cmd.exe`** 数，不要按命令行含 `gradlew.bat` 数——一个构建会展开成 5~11 个父子进程（`cmd → java wrapper → java daemon → …`），按后者数会误判成"并发事故"（我犯过这个错）。
3. **`> Task` 行出现 ≠ 测试跑完**。daemon 连接重置（`MessageIOException: Could not write '127.0.0.1:xxxx' / Connection reset by peer`）会零 BUILD 行、零 XML、零 FAILED。**必须等 BUILD 行。**
4. **不要删 `test-results` 目录**——会触发 `NoSuchFileException: ...\binary\in-progress-results-generic.bin`。
5. **`--tests <单类>` 会触发 stale output cleanup，把同模块其他测试类的 XML 全删**（实测：32 个 XML 掉到 1 个）。**这是今晚发生 5 次的物证丢失主因。**
   - 正确节奏（W60）：**篡改单跑 → 复原 → 全量跑 → 当场快照 + `md5sum -c`**
   - 单类探针必须：① 群里报备 ② 跑完报"已恢复" ③ **不得与主线门禁连着跑**

### 3.2 判绿判据（三条缺一不可）

1. 裸 `> Task :x:testDebugUnitTest` 行，**无 `UP-TO-DATE` / `FROM-CACHE`**
2. `BUILD SUCCESSFUL` 行
3. **XML mtime 晚于该模块最新源码 mtime** ⇒ 否则记「未能验证」，**不许记绿**

### 3.3 破坏性验证（只报绿不算自证）

- **用改名做篡改不可行**——会造成 `Unresolved reference`，红在编译不在断言上，自证无效。我犯过这个错。
- 可用配方：**移动代码形状**（搬出容器块外 / 块内块外各一份 / 改容器名让它走断言失败路径）
- 更可靠且不碰源码的办法：**拿已编译的真实测试字节码，在伪造的仓库根目录上跑真 JVM**（我这轮用过，见 `D:\tmp\guard\run2.sh`）。三次篡改各恰好 1 条失败、精确命中对应断言。

### 3.4 引行号纪律

报告里写 `文件:行号` 必须**当场回读核对**，不许凭记忆或读文件时的偏移推算。本轮我犯过两次：把「`:3242-3244` 是层高 KDoc 开头」记错、把 `layerBackdrop` 钉值 898 说错（实际 **903**，`drawBackdrop` 是 **504**）。

### 5.2 对比度实算（我用 `ContrastMath.kt:84-90` 原公式独立复现，与设计师/移植手数字吻合）

| 起点 | 轨道 α（上沿口径） | 未播轨白42% | 判定 |
|---|---|---|---|

- ⇒ **「底部透气」和「控件行可读」在数学上互不干扰**，改动风险只落在**未播轨道一个元素**上

### 5.3 「往底部收浅」不可行（这是硬墙，别再试）

`PlayerOverlayScrimContrastTest` 有**单调断言**：α 沿停靠比例不得递减。底部比上面浅 = 递减 = **必红**。所以降低"死黑"只有两条合法路：

**两条都治不全**：降平台治"深度"、右移起点治"厚度"。用户同时抱怨了这两条。

### 5.4 团队算出的下一版最优先动作（已归档，本轮未落）
