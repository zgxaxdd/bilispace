### 3.2 真实原因：玻璃有**两条门控不同的链路**

**链路 A —— Dock / 顶栏 / 胶囊（默认是关的）**

`core/designsystem/.../glass/GlassEffect.kt:216-225`：

```kotlin
fun isGlassActive(state: HazeState?): Boolean {
    return config.material != GlassMaterial.OFF &&
        LocalUiStyle.current == UiStyle.IOS &&        // ← 硬性要求 iOS 风格
        state != null && guard.effectiveMotionTier != MotionTier.Reduced && context is Activity
}
```

`ThemeConfig.kt:34` 的 `uiStyle` 默认 = **`MATERIAL`**，且注释自己写着
「**MATERIAL 下不生效且置灰**」。

⇒ **出厂默认下链路 A 全关**，走纯色兜底。用户必须手动切
**设置 → 外观设计 → 界面风格 → iOS**（`AppearanceSettingsScreen.kt:291`）才会亮。
**这不是缺陷，是刻意的发布策略**（`ThemeConfig.kt` 注释：iOS 化覆盖全部 feature 模块，
先作为可选项发布，真机走查干净后再翻转默认值）。

**链路 B —— 播放页控件玻璃（默认就是开的）**

`feature/video/.../VideoPlayerPane.kt:371-403` 的 `playerControlGlass` **不读 `LocalUiStyle`**，
只认：① 「播放页控件模糊」（**默认 true**）② 「播放页控件质感」（**默认 FROSTED**）
③ `resolveGlassBudget(OVERLAY,…).maxBlurLevel > 0`。

⇒ **播放页玻璃默认生效（FROSTED 档）**。但第 15 轮的三处适配里，
**只有"滑块拖动放大"在 FROSTED 档可见**；**「高光档位自适应」只作用于 LIQUID 档**
（FROSTED 根本不画高光边）⇒ 要看它**必须手动切「液态」**。

### 3.4 ⚠️ 真机测量的方法陷阱（我踩了一整轮，别重踩）

**测滑块尺寸时，视频画面会污染所有像素启发式。** 我试过阈值法、游程法、霍夫圆检测、
帧差分，**全部失败**——画面里本来就有大量白色像素（字幕、亮部），`lum>200` 之类判据
会把它们一起算进去，最终返回无意义的值（例如"环 x 范围 0~1271" = 整幅宽，
那其实是控制条已经隐藏了）。

**有效方法**（按可靠性排序）：

1. **先暂停视频**（点画面中央），让背景静止，再做任何像素测量；
2. 用 `adb shell input motionevent DOWN/MOVE/UP` **精确控制按住状态**，
   **不要用 `input swipe`**（有时序竞争，`sleep` 抓不准）。**注意：长按会被识别成
   2.0x 倍速手势**——我实测过一次，控制条被隐藏、冒出 "2.0x" 徽标；
3. 量不出来就**裁图目视比对**（`crop` + `resize` 放大 3~4×，放一条已知长度标尺，
   例如 16dp = 56px @560dpi），比任何启发式可靠；
4. **控制条 2 秒后自动隐藏**（`PlayerChromePolicy.AUTO_HIDE_MS`），抓图必须在窗口内。

## 6. 硬教训（踩过的坑，别再踩）

### 关于"验证"

1. **release 包不能用类名验证**（§3.1）。用 md5 + class 时间戳 + 常量名。
2. **`--rerun` 在多任务命令行下被静默丢弃** ⇒ 一个任务一次调用。
3. **扫源码型守卫读的文件不是测试任务的声明输入** ⇒ 跑前先删 `build/test-results`，
   跑后确认是裸 `> Task` 而不是 `UP-TO-DATE`。

### 关于"守卫"

4. **守卫行号会被同文件新增代码顶掉**。`GlassMountRegistryTest` 钉 `(file,kind,line)`，
   第 15 轮**被它咬了两次**（415→426→443、813→824→842）。它会给实际行号，照抄即可。
5. **扫描断言必须锚"调用形态"，不能锚注释**——扫描器会把注释行清空，锚注释等于锚空气
   （我第一版 `thumbGlassAndRingScaleTogether` 因此**假红**）。
6. **正反例要成对**：只种正向断言，把实现删掉、把关键字留在注释里，照样绿。
7. **门禁证明要覆盖每个分支**：B8-b 只种一条反证的话，`coerceAtMost(1f)` 那一半
   永远不会被发现（我种了两条，分别打中两个分支）。

### 关于"迁移"（最重要）

8. **按旧守卫的计数打基线是错的，要按新检测器的输出打。**
   第 11/12 轮我按"旧棘轮找到的 8 处/4 处"打基线，结果检测器多报出 **90 处**
   （目录级排除在 Lint 里失效）+ **4 处**（多行 `spring(`、字面量藏在 `const val` 里）
   —— **全是漏登，不是缺陷**。正确顺序：**先跑检测器、按它的输出打全基线，再删旧守卫**。

### 关于"改代码"

9. **同一文件、同一报错最多修 2 次**，第 3 次停下换思路。
10. **`fillMaxSize()` 在无界约束下会产生 `Infinity`（崩溃）**。B8-b 第一版我写了它，
    **回读时自己推翻了**：本仓有"Box 包列表 ⇒ 首页白屏"的事故史（`Skeleton.kt:244`），
    且 12 个调用点的 `modifier` 由宿主决定、无法穷举约束。改成**透传约束**才对。
