## 0. 一句话结论

真机 `27-tap-once.png` 里"点一下屏幕出现两套顶栏、两个 ⋮"的**根因不是样式，是没有单一判据**：
会话层（story 信息层 + 互动栏）和播放器层（pane 顶栏 + 控制条）**各持一个显隐布尔、互不感知**。
本轮把"此刻谁该显示"收敛成一个三态枚举 + 四个纯迁移函数，P0-1/P0-3/P0-4 由同一处修复覆盖；
P0-2 由"删掉自绘时钟电量 + 全屏补系统内缩"覆盖。附带做了一轮静态死代码清理。

## 1. 改动清单（按任务书批次）

### A. P0-1 控制层唯一化

| 文件 | 改动 |
| --- | --- |
| `core/swipe/.../SwipeChromeOwner.kt` | **新增**。`SwipeChromeOwner{Story,Player,None}` + `SwipeChromePolicy`：`initial` / `onChromeRequested` / `autoHideTarget` / `onOrientationChanged` / `storyVisible` / `playerVisible` / `LANDSCAPE_EXIT_HINT_MS`。纯逻辑，无 Compose/Android 依赖 |

| `PortraitSwipePager.kt` | 会话持有唯一 `chromeOwner`；方向变化经 `onOrientationChanged`；pane 的显隐请求只走 `onChromeRequested`；底部信息层与互动栏都只读 `storyVisible(chromeOwner)` |
| `VideoPlayerPane.kt` | pane **不再自持** `showCtrl`：`sessionChromeVisible: Boolean?` 非空时是只读投影，写操作经 `onSessionChromeRequest`；`localShowCtrl` 保留给详情页/展开态（行为逐帧不变） |

**关键设计**：写入口**只有一个**（`setShowCtrl`）。点击唤出与 2 秒自动隐藏走同一通道，
差别只在传入的布尔——两个函数会让"自动隐藏"变成"再点一次"那样又点亮控制条（第一版就这么写错过）。

### B. P0-2 安全区

- `VideoPlayerPane.kt`：顶栏 `AnimatedVisibility` 加 `.then(if (isFull) Modifier.statusBarsPadding() else Modifier)`；
  底部 `PlayerCtrlBarHost` 内层 Column 加 `.then(if (isFull) Modifier.navigationBarsPadding() else Modifier)`。
- **删掉 `readPlayerTopMetaText` + `topMetaText` 状态与渲染 + `BatteryManager`/`timeFormat` 依赖**：
  pane 此前在横屏顶栏**自绘了一份"时钟 + 电量"**，与系统状态栏重复 —— 真机
  `32-land-chrome.png` 里标题下面那行 `17:37 46%` 就是它，压住了视频水印也读作"叠字"。
- 条件化（`isFull`）而不是无条件：非全屏（内嵌播放带 / 展开态）的状态栏内缩已由
  `VideoScreen` 的 `.padding(top = statusTop)` 统一承担，再叠一次会把播放带高度算错
  （2026-10-07 真机 dump 的教训）。

### C. P0-3 横屏还原入口（可发现性）

- `SwipeSessionLeaves.kt`：`SwipeLandscapeFab` 增加 `reversed: Boolean = false` 参数 ——
  文案/图标/无障碍标签由叶子**单点**决定（`横屏`↔`竖屏`、`进入横屏`↔`退出横屏`），
  调用点只传 `reversed`，避免两个分支各写一份字符串。
- `PortraitSwipePager.kt`：显隐拆成两件事 ——
  - **是否显示**只看"有画面比例 + 面板未开"（横屏也显示）；
  - **当前方向**只决定 `reversed`。
  - 横屏形态改为 `Alignment.BottomCenter` + `BiliSpacing.xxxl * 2f` 内缩（**不按画幅飘**）；
    竖屏形态保留原 letterbox 下沿几何（`minOf(screenHPx, screenWPx / aspect)`）。
- 转屏后 3 秒内（`SwipeChromePolicy.LANDSCAPE_EXIT_HINT_MS`）该入口**不参与防烧屏变暗**，
  否则"刚转过去就被压到 0.55 alpha"正好抵消"3 秒内可发现"这条验收。

### D. P0-4 横屏设计结论（写进代码）

横屏 = **播放器模式**，明确**不保留**点赞/评论/收藏，理由三条（画面铺满 / 双手握持 /
横屏下没有确认反馈空间）写进 `PortraitSwipePager.kt` 的 rail 门控注释；
横屏保留：返回 / 弹幕 / **退出横屏** / ⋮（播放设置）/ 进度与暂停。

## 4. 未做 / 需要真机的项

- **P1-2「退出后空转解码」**（`PlayWatch rendered=0 skipped=60`）：小横条只显示封面图、
  不挂 PlayerView，因此视频帧没有消费者却仍在解码。正确修法是"没有画面消费端时
  关掉视频轨"（Media3 `TrackSelectionParameters.setTrackTypeDisabled` 或
  `setVideoSurface(null)`），但两者都会改变解码器生命周期，**必须在真机上验证
  "展开回详情页能立刻恢复出帧"**才能落地。本轮已把实验代码回滚，未留下半成品。
- **P1-1「某页全黑 20s」**：本轮修掉的是它的**机制**（缓冲期不再停止观测 + 卡顿阶梯
  四档恢复），真机复现与 20s 阈值仍需按 §6 走一遍确认。
- **P2 视觉细项**：底栏信息区留白比例、状态栏图标颜色这两条属于"看着不对"类，
  需要在真机上逐档调，本轮未动（避免在没有设备反馈的情况下盲改间距）。
