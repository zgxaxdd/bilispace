## 2. 交接书 §3.3「死代码定性」有误：`SwipeMoreSheetContent` 是**被测试依赖的**

交接书 §3.3 末说 `SwipeMoreSheetContent` 无人调用、建议删掉。实测：

```
feature/video/src/test/.../blocked/BlockedUpWiringTest.kt:126
  「为什么必须钉在调用点（W20）而不是只钉 SwipeMoreSheetContent 内部的 if (canBlockUp)」
```

而 `BlockedUpWiringTest.blockEntryOnlyAppearsForPositiveOwnerMid` 会**逐字**断言：

- `canBlockUp = (currentEntry?.ownerMid ?: 0L) > 0L`（调用点必须传）
- `pendingBlockUpMid = currentEntry?.ownerMid?.takeIf { it > 0L }`（第二道守卫）
- `canBlockUp: Boolean = false`（默认值）
- 文件里要有 `if (canBlockUp) {` 且下一行含「拉黑该 UP 主」

⇒ **当前 pager 用内联 `IOSActionSheet` + `buildList` 的写法，会让这条测试红。**
不是"冗余代码"那么简单：它把 PT-06 的验收口径钉在**旧的 `SwipeMoreSheetContent` 调用点**上。
处理方向（见 §4）：要么把 pager 改回调用 `SwipeMoreSheetContent`，要么同步改测试口径 —— 二选一，
不能删文件了事。
