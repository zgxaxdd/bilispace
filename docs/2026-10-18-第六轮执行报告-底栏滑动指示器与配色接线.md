## 2. 底栏滑动指示器 + 横向拖动切 Tab（需求 3 的"控件拖拽动效"，本轮落地）

### 为什么推翻旧决定
旧实现在代码里写着"去掉滑动指示器"并给了两条理由。两条现在都被解决了，且用户从第一轮起就点名要这一项：
1. **"指示器与图标两套坐标容易错位（每格 4dp）"** —— 旧实现是每个 Tab 各画一层底色再用 offset 凑。新实现把指示器放在**与图标同一个 Row 起点**，`x = index * itemSize + innerPad`，与图标格**共用同一套测量**，不存在第二套几何。
2. **"切换位移读作抖一下"** —— 位移曲线改用 `LiquidIndicatorMotion.positionSpec()`（spring），并叠加"拖动距离越大横向拉伸越多（≤1.16）"的液滴形变；拖动中也一样（阻尼 0.55 跟手 + 越界橡皮筋 28%）。

### 实现要点
- 两套驱动**互不混写**：基点 `Animatable`（点 Tab 时 spring 滑过去）+ 拖拽偏移 `DampedDragState`（跟手），在 `offset { }`（布局期）与 `graphicsLayer { }`（绘制期）相加 —— 拖动中每帧只改变换、**零重组**。
- 松手按 lattice 吸附并**直接切 Tab**：`DampedDragState.onRelease` 现在返回吸附目标 px，`dampedHorizontalDrag` 增加 `onSettled` 回调（designsystem 侧小改，默认参数向后兼容）。不等动画结束再读 offset —— 那样晚一帧，且会在过路格位上误触发。
- 拖动切 Tab 时基点**瞬移**（`switchedByDrag` 标记）：手指已把指示器带到位，若再让 spring 从旧基点滑过去，会和"拖拽残余归零"反向叠加，读作抖一下。
- 只消费**水平**位移：纵向滚动不受影响（`detectHorizontalDragGestures` 语义）。
- `reduceMotion` ⇒ 全部瞬时到位。

## 3. 播放器互动栏计数动效（与详情页统一判据）

- 计数**真值同源**（详情与播放器都读 `VideoViewModel.interaction`），因此不存在"两边数字不一致"；
- arm（"这次要弹"）状态两侧各自持有 —— 判定依据：两处 UI **互斥可见**（互动栏只在全屏连播、详情操作栏只在紧凑详情），不会同屏一边弹一边不弹；
- 播放器侧保留自有的"上浮滚动"视觉（不把详情的缩放弹跳搬进来，避免同一计数在两个界面两种语言），但**判据换成** `shouldAnimateVideoActionCountChange`：只有本地操作 arm 时才滚 ⇒ **后台回填/切视频不再乱滚**（这是修掉的一个真实小毛病）。
