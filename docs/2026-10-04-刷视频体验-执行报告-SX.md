### 3.1 对任务书的一处更正（W4/W29：以源码为准）

任务书 §3 SX-04 要点②写"app 侧 = **服务端回传的** `idx`"。**回读源码后更正**：改动前的推进是
`SwipeCursor(sourceId = id, idx = idx + 1)`（`SwipeSources.kt` 原文），**并不是**服务端回传的 idx，
而是一个从 0 起的本地页计数器。本批**保持这条历史口径逐字不变**（MOBILE 零回归红线），
只把 web 侧的 `webPage` 并列引入。→ 建议下一轮修正任务书该处表述。

### 3.2 决策：为什么**不**直接用 `FeedCursorPolicy.loadMoreCursor`

首页口径是"**档位**决定推哪个字段"（WEB 档把 `appIdx` 归零）。接力不能照搬：WEB 档下
`fetchWebFeed` 在 WBI 密钥取不到时会**回退** `fetchMobile(cursor.appIdx, …)`
（`FeedRepository.kt:122-136` 的 catch 分支），`appIdx` 若归零则回退恒拉第 0 页。
故接力对两个字段**同时 +1**。`FeedCursor` 类型本身仍复用 core:feed 的那一个，未另造。

## 5. 决策点结论

### 5.1 决策 D-1（SX-04）：刷视频推荐跟随"推荐来源" —— **已实现**

- 接力改走**感知来源**的游标重载，游标由接力自持（app 侧 `appIdx` / web 侧 `webPage`）。
- **行为变化（有意，用户决策）**：选 WEB/MERGED 后刷视频的**内容构成会变**（web 只有普通视频、
  且没有"不感兴趣"）。**默认仍是 MOBILE，默认路径逐字未变**（`SwipeFeedCursorPolicyTest` 钉住）。
- **旧入口处置**（任务书 §7 A.1）：`grep` 确认删除前**只剩 `HomeFeedSwipeSource` 一个调用点**
  ⇒ **收敛删除**，同一提交说明。

  用户实际看到的档位描述与 WEB 档真实内容差异是否一致；建议与 L4-122 真机走查**同批**处理。
- **真机**：L4-122 **未能验证**。

### 5.2 决策 D-2（SX-10）：评论区只透明、不模糊 —— **结构侧已落地，性能门禁未验**

- 面板底色 `surface.copy(alpha = 0.72f)`，**零模糊**、**不新增图层**（只把既有一次填充改成半透明）。
- 守卫 `swipeCommentCardIsTranslucentAndBlurFree` 咬住"面板文件里模糊入口计数 = 0"这条硬门禁。
- **⚠️ 硬门禁未过（因为测不了）**：D-2 要求"改动后滚动帧率**不得劣于** SX-06 测得的基线"，
  而真机不在线 ⇒ **基线不存在** ⇒ 该门禁**无法判定**。按任务书口径"劣化即不通过"，
  本项**不声明通过**，状态 = **结构侧通过 / 性能门禁未能验证**。缺：真机 + `dumpsys gfxinfo framestats` ≥3 轮。
- 配套的 SX-07（面板展开动效）已同区域落地，且动效走 token、不新增 animate*AsState。

### 5.3 决策点（SX-12）：MERGED 是否对齐上游参数 —— **不对齐，单独立项**

- **三态结论**：**部分有效**。机制层有效（两条独立证据：`FeedRepository.kt:184-187` 两个 `async`
  走 `getWeb`/`getSigned` 两条不同链路；`FeedMergePolicyTest` 7 例覆盖交错/去重/**单边存活**，
  另有既有结构守卫）；运行时层**未能验证**（无真机，拿不到实机计数）。
- **"app 半边复用 fetchMobile"有无实际坏处**：逐项排查后**未发现**（不会把两路边算成一路；
  toast 不重复；`interestChoose` 不丢；未发现缓存键冲突 —— 静态核查，未抓包）。
  真实差异是 **app 半边推荐内容分布**（bbspace = MOBILE ∪ WEB；上游 = android_hd ∪ WEB(V8)），
  **不影响"MERGED 是否真的合并了"**这一命题。
- **是否对齐上游**：**不并入本批、单独立项**（BACKLOG **MG-01**）。理由：①需要新增一条签名链路
  （`android_hd` 身份头 + percent-encode + cookie 剥离 + buvid3 引导）属新增能力（铁律 11）；
  ②收益是**内容构成**而非正确性修复；③**无真机无法判断收益正负**；④与 SX-04 同批会放大数据层
  变更面、出问题无法归因（W37）。
- **本批唯一落地**：MERGED 计数日志改为 release 可见 —— 解除了 L4-123 的取证障碍。

### 5.4 新增决策（SX-09）：点赞**没有**改成乐观更新 —— 登记为欠账

任务书 SX-09 要点③字面要求"失败要回滚"，而"回滚"只在**乐观更新**下才有意义；
