### 3.1 SX-04 的一个代码级更正（W4/W29：以源码为准）

任务书 §3 SX-04 要点②写"app 侧 = **服务端回传的** `idx`"。**回读源码后更正**：
改动前的接力推进是 `SwipeCursor(sourceId = id, idx = idx + 1)`（`SwipeSources.kt:32` 原文），
**并不是**服务端回传的 idx，而是一个从 0 起的本地页计数器。
本批**保持这条历史口径逐字不变**（MOBILE 零回归红线），只把 web 侧的 `webPage` 并列引入。
→ 建议下一轮修正任务书该处表述。

### 3.2 决策：为什么**不**直接用 `FeedCursorPolicy.loadMoreCursor`

首页口径是"**档位**决定推哪个字段"（WEB 档把 `appIdx` 归零）。接力不能照搬：WEB 档下
`fetchWebFeed` 在 WBI 密钥取不到时会**回退** `fetchMobile(cursor.appIdx, …)`
（`FeedRepository.kt:122-136` 的 catch 分支），`appIdx` 若归零则回退恒拉第 0 页。
故接力对两个字段**同时 +1**，未参与当前档位的字段递增无副作用。
（`FeedCursor` 类型本身仍复用 core:feed 的那一个，未另造。）理由已写进 `SwipeFeedCursorPolicy` 的 KDoc。

### 5.3 决策点（SX-12）：MERGED 是否要对齐上游参数 —— **不对齐，单独立项**
