## 1. 铁律（沿用本仓既有纪律，不得放宽）

1. **子代理的使用（用户明确要求）**：允许用子代理，但**子代理不得承担任何重要工作**，只能是辅助：
   代码检索/定位、只读侦察（"这条链路有哪些调用点"）、跑只读命令、汇总纯信息。
   **所有判断、设计、编码、验收、写文档、下结论必须由主代理亲自完成**；
   子代理的结论与源码不一致时，**以主代理自己读到的源码为准**。
   禁止把"实现某功能""跑完整批验收"整包丢给子代理。

### 2.2 推荐来源三档（上一会话移植的 PT-10，务必先读懂再动 SX-04/SX-12）

- `FeedApiType { WEB(0), MOBILE(1), MERGED(2) }`，**默认 MOBILE**，兜底也是 MOBILE（`core/settings`）。
- 首页走**游标重载** `FeedRepository.fetchFeed(FeedCursor, …)`：内部按 `appSettings.feedApiType.first()` 分派 → `fetchMobile` / `fetchWebFeed` / `fetchMergedFeed`。
- **旧入口 `fetchFeed(idx: Long, …)` 恒走 app 协议（`fetchMobile`）**，不随设置切换——
  这是上一会话**有意的偏离**（任务书 D-2）：刷视频接力依赖 app 协议回传的 `idx`，而 web 协议**不下发 idx**（恒 0），
  若旧入口也按设置切 WEB，接力会拿 `idx=0` 反复拉同一页 = 静默死循环。该不变量已有守卫：
  `core/feed/src/test/…/FeedSourceDispatchGuardTest.legacyThreeArgEntryAlwaysUsesAppProtocol`。
- MERGED 的实现：`coroutineScope { async(web) + async(mobile) }` → `FeedMergePolicy.mergeFeeds(web, mobile)`（交错、按 bvid/aid 去重）；
  运行时会打 `D FeedRepository: MERGED 档：web=N mobile=M`（真机已见 `web=18 mobile=9`）。
- WEB 档的 web→FeedItem 映射在 `core/feed/…/WebFeedMapper.kt`（含自有万/亿与时长格式化器、协议相对地址补全）。
