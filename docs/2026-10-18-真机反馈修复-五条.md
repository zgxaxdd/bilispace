## 1. 弹簧拖拽：修掉三个真 bug（用户首要诉求）

用户原话："**当前弹簧拖拽效果不符合预期，且存在错位和 bug**。我想要的是：按压时元素膨胀；拖拽时沿受力方向拉伸；松开后带弹性晃动并回归原状。"

### Bug ①：错位 —— **双状态源 + touch slop 双重损耗**
| 根因 | 说明 |
|---|---|
| **双 Animatable 相加** | 旧实现是「基点 `Animatable` + 拖拽残余 `Animatable`」在 `offset{}` 里相加。两者各自 `scope.launch` 异步更新，切页时基点 `snapTo`、残余清零**不在同一帧生效** ⇒ 必然出现一帧跳变 |
| **touch slop 被吞** | `detectHorizontalDragGestures` 内部走 `awaitTouchSlopOrCancellation`，**触发前的位移被丢弃**，首次回调只给"超出 slop 的那一点" ⇒ 指示器**永久落后手指约 8dp** |
| **漏加 innerPad** | 指示器宽 40dp 而格子宽 48dp，要在格内居中必须 `x = index*pitch + innerPad`，旧实现漏加 ⇒ **每格左偏 4dp**（正是旧注释自己警告过的数字） |

**修复**：
- **单一状态源**：只保留一个 `indicatorX` 作为**绝对位置**，手势层直接上报绝对位置（`base + 手指位移`）⇒ 结构上不可能错位；
- **无 slop 手势**：照上游 `inspectDragGestures` 的做法自己写 `awaitEachGesture` + `awaitFirstDown(PointerEventPass.Initial)` + 逐事件 `positionChange()`，**从按下第一帧就上报**，并用 `position.x - downPosition.x` 的绝对式（不累加增量，丢帧也不漂）；
- **补 innerPad**：`x = indicatorX + innerPadPx`，并写测试断言"指示器中心必须与格子中心重合"。

### Bug ②：首/尾档能拖出可视区
旧实现用**对称**边界 `±(n-1)·pitch`，于是第一个 Tab 还能往左拖、最后一个还能往右拖。
**修复**：边界按当前档位**非对称**计算（首档 `min=0`、尾档 `max=0`、中间档两侧各 1 格防"一甩到底"），`rubberBandOffset` 同步支持非对称软边界。

### Bug ③：松手不晃（没有弹性）
旧实现用 `tween` 回弹 —— **tween 单调，永远不会越过目标再回来**，数学上就不可能"晃"。
**修复**：新增 `releaseSpec()`（阻尼 **0.62** = 欠阻尼，过冲约 6~8%，两次振荡内收敛）。点 Tab 的位移仍用临界阻尼（1.0）—— 切页不该晃，只有松手才晃。

### 按压膨胀（用户明确要求的方向）
新增 `pressAnimation` + `LiquidIndicatorMotion.PressedScale = 1.18`：按下时指示器**放大 18%**。
> 这与本仓按钮族的"按压缩小"（0.97/0.92）相反，是**刻意的**：按钮是"被按下去的实体"，而指示器是**液态的一块**，压上去应该"被挤出来"。两种物件的物理语言不同。

### 拖拽拉伸
`scaleX = pressScale × (1 + |偏离基准|/pitch × 0.16)`（上限 1.16），`scaleY = pressScale` —— 沿受力方向拉长，松手回 1。

### 回归守卫（新增 11 条，`DockDragRegressionTest`）
把三个 bug 逐条钉死，包括**反向断言**（"漏掉 innerPad 的中心应当偏离 2dp"——保证测试真能抓到那个 bug）。

## 3. 首页性能：砍掉每卡玻璃（最大收益项）

用户原话："**减少首页模糊效果的使用面积**。"

**盘点结论**（按面积）：根录制整屏 3.56 Mpx/帧、首页私有背板 3.56 Mpx/帧、顶栏消费 0.86 Mpx、Dock 0.28 Mpx、
**每卡封面包裹层 ≈0.9 Mpx/卡**（默认单列每滚动帧 ≈**2.3 Mpx**）、每卡 2 角标采样。

**结构性阻断（重要）**：原计划"每卡角标改采首页共享背板"被反编译证伪 —— miuix `LayerBackdropNode.draw` 是
`record { drawContent() }` 录制**整棵 pager 子树**，角标就在其中 ⇒ 会**采样到自己**（自采样反馈）。
本仓 `HomeScreen:201` 的注释"顶栏是悬浮兄弟节点，无自采样"正是同一条规矩。**未硬改，改走 Alt-1**。

**Alt-1（已实施）**：删除每卡 `rememberLayerBackdrop`、挂载、`glassBadgeSurface` 整段（含 `drawBackdrop`）；
角标统一走**原本 MATERIAL 档就有的非玻璃分支**（黑 62% + 白字），iOS+LIQUID 也收口到它。
- 收益：默认单列每滚动帧少 ≈2.3 Mpx 录制 + 每卡 2 次 blur；新卡进视口不再首建 per-card 玻璃链（直击 `worst=132ms` 尖峰）；
- `HomeVideoPage.kt` 现在**玻璃符号 grep = 0**；挂载点从 12 降到 10，登记表已同步（含删除理由）。

## 4. 首页顶栏：修掉"滑动 bug"（认证待明确）

### 滑动 bug 的静态根因（代码结构上确实缺一环）
`topBarOffsetPx` 只有 3 个写入点（滚动增量、切页复位、刷新回顶），**没有 fling 结束时的吸附不变量**
⇒ fling 若在 `offset ∈ (0, height)` 结束（列表没滚到顶、或甩回顶部但无 over-scroll 余量），
顶栏会**停在半隐状态不动** —— 用户读作"卡住不回弹"。

**Fix-1**：新增 `HomeTopBarScrollState` 状态机，`onPostFling` 收尾吸附到最近端（`< h/2 → 0`，否则 `→ h`），
用 `LocalAnimations.morph` token 动画，`reduceMotion` 直接落位。

**Fix-2**：`isScrolling` 此前实际是"offset > 0"（半隐/全隐），导致**静止半隐时玻璃被锁在 `allowRealtime=false` 降级态**
（发灰、不跟随）。改为真正的滚动布尔，并采用**权威 + 兜底**双保险：
`onPostFling` 立即清零（权威）+ **120ms 静默计时器**兜底（`onPreScroll`/`onPostScroll` 任一有位移即重启）
—— 不再依赖"零速度抬手是否派发 `onPostFling`"这个假设。

### 认证（用户原话"重点处理认证相关优化"）
**全仓静态排查结论**：`feature/home` 顶栏**没有任何认证/实名/verify/buvid 逻辑**，唯一接触点是**头像入口**。
发现一个真问题：未登录时头像只画一个灰色 `Person` 图标，**与"已登录但头像没加载出来"完全无法区分**，
用户点下去跳到档案页才发现没登录 ⇒ 多一次无效跳转。
**已修**：未登录（`profileAvatar == null`）时给头像加主色细描边（1.5dp）+ 图标转主色 +
`contentDescription = "未登录，点按登录"`。`onClick` 不变。

> ⚠️ 若用户说的"认证"是别的（登录后头像不刷新 / 直播实名门槛 / 某种 token 刷新），需要再明确 —— 当前只覆盖了"未登录态不可区分"这一处。
