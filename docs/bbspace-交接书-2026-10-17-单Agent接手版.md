## 7. 数字陷阱（今晚栽过的，动手前必读）

### 7.1 几何一变，所有对比度数字集体失效

设计师曾用**旧几何**（0.36 起点时代）算出"轨道提亮能让平台余量 5%→23%"，据此推出"下一版先动轨道白度"的**路线结论**。核查员用原公式复算发现：

```
实际（0.50 起点）：轨道白 0.42 = 3.15、提亮到 0.50 = 3.79
已播:未播 = 3.09（现状） → 2.57（提亮后）   ← 提亮会破 3:1 "一眼可辨"门槛
```

**结论：轨道提亮不是纯增益，它拿"已播/未播可辨度"去换"平台余量"。设计师已主动撤回该路线，不要再执行。**

> **纪律 W63/W73**：引用任何历史文档里的对比度数字前，**先核对它写作时的几何是否还存在**。几何一变（起点/平台/层高任一），该文档里所有比值都要重算——**不是只算改动的那一个**。
> **作废的规格数字不许删，要封 `<details>` 并写明错因**——删了下轮还会有人凭记忆重推一遍。

### 7.2 同一公式，黑底和白底结果差 1.6:1

设计规格里"加芯片底"曾写 `a_eff = 0.88 + (1−0.88)X`——**那是黑芯片公式**，规格定的是**白**底。正确是 `a_eff = 0.88 × (1−X)`（白底提亮背景）。

```
黑底 6.90:1   vs   白底 5.28:1
```

**引用对比度数字必须标明"用的哪种底"。**

### 7.3 三个口径并存，报数必须带"哪个态 + 哪层"

```
L-a 中心     距底 70/78dp    全屏 3.21    ← 源码 KDoc（偏松）
L-b 上沿     距底 71/79dp    全屏 3.15    ← 当前守卫
L-c 带 min   两端+抗锯齿外缘 全屏 3.12    ← 待落地
```

**全屏态永远比内嵌态紧**（底部留白 16 vs 8），只说"3.1x"没有意义。

### 7.4 f 的方向要先找到约定
