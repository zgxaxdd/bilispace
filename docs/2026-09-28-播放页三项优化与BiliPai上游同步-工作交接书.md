## 3. 实现要点（带行号，行长以当前工作区为准）

### 3.1 竖屏视频贴合预览框（#1）

- 宽高比来源：`videoAspect`（`VideoScreen.kt:215` 附近，`remember(videoState.currentStream)`）
- 竖排：`naturalVideoH = maxWidth / videoAspect`，`targetVideoH = minOf(naturalVideoH, (maxHeight - statusTop) * 0.70f)`
  → `VideoScreen.kt:497-503`；**70% 是"详情区保底 30% 可视高度"的截顶**，不是随便取的
- 比例过渡：`aspectMorph`（`Animatable`）+ `LaunchedEffect(baseVideoPx, targetVideoPx)` → 200ms standard
- 平板/折叠屏：取「与视频同比例的最大矩形」→ `VideoScreen.kt:365` 附近（宽度触顶则按比例收高）
- 形变高度在**布局期**求值：`Modifier.playerMorphHeight` → `VideoScreen.kt:700`

### 3.2 播放器 / 内容衔接（#2 定稿版）

三层，全部静态、零逐帧成本：

1. **底部圆角**：`CompactPlayerShape`（`BiliRadius.playerCompact` = 20dp，仅下两角），播放带自身 `clip` 保证
2. **高光描边**：`Modifier.playerSeamStroke` → `VideoScreen.kt:721`，调用点 `VideoScreen.kt:603`
   - 水平渐变：透明 → 主色 0.55 → 白 0.90 → 主色 0.55 → 透明（两端淡出）
   - 线宽 `SEAM_CORE_DP = 1.2f`（乘 density 得 px —— dp 字面量棘轮没有余额）
3. **BiliPai 顶栏同款纯色渐进消隐**：`Modifier.topSolidProgressiveFade` → `VideoScreen.kt:571`
   ```kotlin
   .topSolidProgressiveFade(
       surfaceColor = Color.Black,          // 播放器的"底色"就是黑
       fadeHeight = seamFadeHeight          // BiliSpacing.xxxl * 1.25f = 40dp
   )
   ```
   - 实现文件：`core/designsystem/.../component/ProgressiveFade.kt`（项目已移植，含 `peakAlpha` 扩展）
   - 配方：**Telegram/Nagram 非线性 5 档停靠点** `1.0 / 0.9098 / 0.6902 / 0.3765 / 0` at `0 / .25 / .5 / .75 / 1`
   - ⚠️ **不要换成线性渐变**：线性插值感知亮度不均，会在接缝下方留一道生硬灰带（马赫带），上一版就是因此被判"丑"

### 3.3 下滑进入全屏（#3）

- 形变状态机：`fullscreenMorph` / `aspectMorph`（`Animatable`）→ `VideoScreen.kt:237` 附近
- **所有形变值只在布局期/绘制期读取**（`layout{}` measure 块、`graphicsLayer{}`、`offset{}`、`onGloballyPositioned`），
  形变全程零重组；未新增 `animate*AsState`（FrameBudgetLintTest 棘轮钉着）
- 手势：`Modifier.pullDownToFullscreen` → `VideoScreen.kt:764`
  - **走 Initial pass**：LazyColumn 在 API 31+ 自带 overscroll stretch，会在列表顶部把下拉事件自己消费掉；
    Main pass 等不到，必须在"父先于子"的 Initial pass 里裁决
  - 起手条件：按下点在播放带下方 + 纵向占优 + `!detailListState.canScrollBackward`（列表已到顶）
  - 进度 = 手指 y 在「播放带底边 → 窗口底边」区间上的直接映射（不是阈值阶梯）
  - ⚠️ `AwaitPointerEventScope` 带 `@RestrictsSuspension`：块内**不能**直接调 `Animatable.snapTo`，
    必须经外部 `CoroutineScope` 派发（见 `VideoScreen.kt:764` 的注释）
- 详情区：布局尺寸按 16:9 基准固定，形变期只做 `offset + graphicsLayer(alpha)`，**不重新 measure 列表**
- 列表状态提升：`detailListState` 由 `VideoScreen` 持有（键仍是 `videoState.ids.aid`），
  经参数下发给 `VideoDetailPage`（这是 `VideoDetailPage.kt` 那 4 行改动的全部原因）
- 退出全屏：`exitFullscreen()` 反向播放同一动画；平板/横屏无紧凑形变链时直接 `snapTo(0)`

## 6. 踩过的坑（真机教训，**别再走一遍**）

1. **线性渐变 = 马赫带灰带**。用户判"丑"的直接原因就是它。任何"消隐/衔接"渐变都必须走
   `ProgressiveFadeDefaults.createStops`（Telegram 非线性 5 档）。
2. **方向**：光要**向下**洒进内容区（"播放器里的光溢出来"）。向上飘的粒子读作灰屑，用户明确否掉。
3. **粒子 / 光幕 / 星芒 / 扫光**在深色底上读作噪点，用户要求"全部删掉"。接缝**只该有**：
   一道描边 + 一层消隐渐变 + 圆角。
4. **「文字透明＋字内液态玻璃」这条路真机不通**：`TextLayoutResult.getPathForRange` + `clipPath` +
   miuix `drawBackdrop` 的组合在真机上渲染成**矩形空心块**（有截图证据），不是字形。
   若还要做玻璃文字，必须先解决"字形 Shape → `Outline.Generic`"（会 +1 `ListAllocationStructureTest`
   的 Path/Outline 棘轮，需按项目惯例连棘轮一起改并写明理由），并确认 miuix `drawBackdrop` 是否吃画布 clip。
5. **`AwaitPointerEventScope` 带 `@RestrictsSuspension`**：手势块内不能直接调用外部挂起函数
   （`Animatable.snapTo` 会报 "Restricted suspending functions…"），必须 `scope.launch { }` 派发。
6. **`BoxWithConstraintsScope` 带 `@LayoutScopeMarker`**：`maxHeight`/`maxWidth` 在内层 `Box` 的 content
   作用域里**不可见**（编译期报 "cannot be called with an implicit receiver"），必须提前算成普通 val。
7. **不要用按行 splice 改这些文件**：PowerShell `Get-Content` 与 .NET 的行切分在含中文/CRLF 的文件上不一致，
   本次据此切坏过 `VideoScreen.kt`（丢了竖排分支尾部 + 封面垫底块 + `playerMorphHeight`），
   已按 git HEAD 内容修回并通过编译。**改动一律用 edit 工具或 .NET + 显式校验**。
8. **dp 字面量棘轮已满（980/980）**：新增尺寸只能用 `BiliSpacing.*` token 或
   `常量 * density.density` 这类不含 `.dp` 的写法；`0.dp` 也算一处。
9. **miuix 玻璃链必须 `remember` 住**（`DrawBackdropElement.equals` 对 lambda 做引用比较，
   `update()` 末尾无条件 `invalidateDrawCache()`），GlassDrawChainStructureTest 钉着这条。
