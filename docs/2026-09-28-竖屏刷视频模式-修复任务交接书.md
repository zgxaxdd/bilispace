### 2.2 接缝光感（另一个已完成的功能，勿破坏）

用户在接缝区域（播放器下方）反复打磨后的定稿结构（`VideoScreen.kt` 竖排分支）：
**图层序：详情背景层 → 光晕层 → 简介内容层 → 播放带**。要点：
- 光晕 = BiliPai coverGlow 原参数（封面**原色**、深 0.48/浅 0.38、`topSolidProgressiveFade` 160dp）——**在内容之下**，不遮挡文字；
- **描边色 = 光晕色**（`seamStrokeBase = seamGlowColor`，用户定稿"描边与下方光同一个颜色"）；
- **背景层与光晕层都上移一个圆角半径（`BiliRadius.playerCompact`）**——播放带底部圆角切掉的月牙区是透明的，光沿圆角轮廓透出（"光覆盖到圆角"的几何原理）；

## 3. 已修复的 bug（防止接手 agent 重复踩）

### 3.1 队列恒为空 → "无法上下滑动、没有内容"（已修）

**现象**：全屏后无内容可翻（pager 只有 1 页）。
**根因**：bbspace 的相关推荐来自详情响应的 relate 模块，其 `basic.uri` 是 **aid 格式**（`bilibili://video/{aid}`）→ `VideoTargetTool.bvid(uri)` 解析为 **null** → 旧版 `SwipeEntry` 映射只认 bvid，**整页 40 条推荐全部被丢弃**。诊断日志证据：
```
PortraitSwipe: session: anchor=BV1Kyas6wEuz relates=40 queue=0     ← 修复前
PortraitSwipe: session: anchor=BV1Kyas6wEuz relates=40 queue=5     ← 修复后（去重后 5 条）
PortraitSwipe: activate: portrait=true queue=5 active=true
```
**修法**：`SwipeEntry.key = bvid.ifEmpty { "aid:${target.aid}" }`（bvid 优先/aid 兜底），全链路（去重、页身份、requestedKey、openSwipeTarget 短路）统一用 key；映射函数只在 bvid/aid 全缺时丢弃。
**注意**：修复后仍建议按 §4.1 把 bvid 补全（aid-only target 正是下一个 bug 的嫌疑源）。

### 3.2 上下滑被亮度/音量手势抢走（已修）

`videoGestures` 拖过 slop 后**无条件 `change.consume()`**（含 `DragType.None` 的中间区域）→ pager 永远收不到垂直拖动。修法：新增 `verticalDragPassthrough: () -> Boolean`，pager 会话激活时垂直拖动**不判定亮度/音量、不消费、waitForAllUp 让位**（与既有 zoom 让位同款）。

### 3.3 其他已修（详见 `docs/ai-loop/report-2026-09-28-C4.md` §五）

锚点 target 用 activeTarget（完整 aid/cid）；audio/session 重试（`swipeAnchor == null` 判据防锚点漂移）；`rememberUpdatedState(pages.size)` 防 pageCount lambda 被记住（"无限刷"静默失效）；`requestedKey` 防目标震荡；播完自动翻页。

## 4. 待修复问题（本次交接核心）

### 4.1 ❗无法播放下一个视频（最高优先）

**现象**：滑动翻页可以了，但翻到下一页后**视频不播放**。
**已掌握的线索链**：
1. `PortraitSwipePager` 翻页 → `onSwipeTo(entry)` → `VideoViewModel.openSwipeTarget(entry)` → `playbackController.openVideo(entry.target)`；
2. `entry.target` 来自 relate 卡 = `VideoTarget.Ugc(aid=xxx, cid=yyy, **bvid=null**)`（§3.1 的 aid 格式 uri）；
3. **嫌疑：`StreamPlaybackSession` 对 "aid-only、bvid=null" 的 target 解析失败**（详情/取流链路可能以 bvid 为主键）。上一个 agent 用 adb 上滑复现时出现过**整页退回首页**（截图 `docs/ai-loop/shots/c6_swipe_ok.png` 显示 MainActivity 首页），怀疑 `openVideo` 失败后走异常/回退链路把 Activity 收了——**接手 agent 必须先用 logcat 复现确认**（见 §6 复现步骤），不要直接猜。
4. **修复路线（按优先级）**：
   - **路线 A（推荐，治本）**：**补全 bvid**。查 `RelateCard` 的 gRPC/proto 响应里是否还有 bvid 字段未被解析（`VideoDetailRepository.mapRelates` 只用了 `basic.uri` 解析）；若没有，用 **av→BV 本地换算**（算法确定、纯计算）：先查 `VideoTargetTool`/`BiliConstants` 是否已有 `av2bv`（BiliPai 有类似工具），没有就移植一个 av2bv 函数，在 `mapRelates` 里 `bvid = bvid(uri) ?: avToBv(aid)`。补全后 `entry.target.bvid` 全程非空，所有下游（播放、key、身份判断）都回到主路径。
   - **路线 B（与"学习 BiliPai"直接对齐）**：**移植 BiliPai 的独立 relate 接口**（`VideoRepository.getRelatedVideos(bvid)` → `api.getRelatedVideos(@Query("bvid"))`，响应 JSON 直接带 `aid/bvid/cid/title/pic/owner/stat/duration`，见 BiliPai `RelatedResponse.kt`）。可作为 `loadMoreSwipeQueue` 的第二个数据源或直接替换 relates 种子。bbspace 侧在 core 网络层加该接口（沿用 `BiliRestClient` 签名通道，参数只有 bvid，`/x/web-interface/archive/related` 一类 App 接口）。
   - 路线 C（兜底）：确认 `StreamPlaybackSession` 是否本可支持 aid-only；若支持则修 pager/VM 侧的状态流转。
5. **排查要点**：`adb logcat | grep -Ei "PortraitSwipe|StreamPlayback|PlaybackController|FATAL|Exception"`，复现一次上滑，看是否有 session 解析异常；同时观察 Activity 是否 finish（`dumpsys activity activities | grep bbspace`）。

### 4.2 ❗下滑时出现"旋转动画"

**现象**：用户每次下滑（很可能是"下滑进全屏"或"翻到横屏视频"）出现屏幕旋转动画。
**最可能根因（已定位到具体代码）**：`VideoScreen.kt` 里的全屏方向请求：
```kotlin
DisposableEffect(act, fullOn, settingsState.playback.autoRotateFullscreen, isPortraitVideo) {
    act?.requestedOrientation = if (fullOn && settingsState.playback.autoRotateFullscreen) {
        ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE   // ← 全屏请求横屏 = 旋转动画
    } else {
        ActivityInfo.SCREEN_ORIENTATION_UNSPECIFIED
    }
}
```
- 若用户设置 `autoRotateFullscreen` 开启，进入全屏即请求横屏 → **转屏动画**；
- 或刷到**横屏视频**时 `isPortraitVideo` 翻转触发重设 orientation → 又转一次。
**修复方向**：**上下滑会话激活期间（`swipeSessionActive` / story 模式）禁止方向切换**——全屏刷视频应锁定竖屏（与抖音/BiliPai 的竖屏 pager 行为一致）；BiliPai 的 `PortraitVideoPager` 全程只做 immersive 系统栏管理、不请求横屏。同时在会话结束时恢复原逻辑。

### 4.3 待观察：上滑后整页退回首页（可能与 4.1 同源）

上个 agent 的 adb 复现中出现（`c6_swipe_ok.png`）。三种可能须逐一排除：
a. `openVideo(aid-only)` 失败 → 异常链路（见 4.1）；
b. **`VideoPlayerPane` 的「回首页」按钮/`pullDownToFullscreen` 的 onSettle** 被滑动误触（检查滑动是否被识别为点击）；
c. `handleBack`/`popPage` 链路被触发。
**排查**：复现时抓 `PortraitSwipe`、`VideoDetailNavBus`、Activity finish 日志。

## 5. BiliPai 完整调研笔记（"没有的就移植"清单）

### 5.1 数据源（已核实的关键事实）

- **BiliPai StoryScreen（首页刷视频入口）用的是首页推荐流分页 `getHomeVideos(idx)`**（`StoryViewModel.loadInitialStories/loadMoreStories`，倒数第 3 页触发 loadMore），**不是** story 接口；
- **`StoryRepository.getStoryFeed`（`x/v2/feed/index/story`）用在详情页竖屏 overlay**（`VideoDetailPortraitOverlayAdapter`：story 流优先、失败回退 related）；
- **`getRelatedVideos(bvid)` 是独立接口**，JSON 直接带完整 `bvid`（所以 BiliPai 不存在 bbspace 的 aid-only 问题）。
- bbspace 现状：relates 接力（种子）+ `fetchFeed(idx)` 分页补货（已实现）——**缺 BiliPai 的"独立 relate 接口"**（见 §4.1 路线 B）。

| adb swipe 起点落在播放带内会被 pull-down 放行 | 起点必须取播放带底边下方；本机竖屏视频临界约 y=2000 |
| OplusViewSeamless：onAnimationEnd 不送达 | 阶段推进靠 `SeamlessTransitionState` 800ms 兜底；`finishCurrentAnimation` 不轻调 |
| story 模式与 beginSwipeSession 互斥 | story 锚点/队列由 `bootstrapStorySession` 全权负责（VideoScreen 在 `effectiveStoryMode` 下跳过） |
