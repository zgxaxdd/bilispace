## 二、第 2 条：播放页控件 + 首页模糊（用户说"都没完成"）

### 2.1 播放页控件 —— 截图证据成立，已重构

用户截图实测：整块画面被压一层黑、底部近乎死黑、中间一块半透明灰矩形。

**根因不是"值调大了"，是「黑遮罩铺满整层」这套语言**：

| Token | 旧值 | 问题 |
|---|---|---|
| `PlayerCtrlBarScrimBrush` 覆盖范围 | **整层 118/126dp** | 从层顶到底都在压黑 |
| `PlayerOverlayScrimBottomEnd` | 0.88 且从 f=0.50 起平坦 | 底部 50% 层高是同一块死黑 |
| 层内 f=0.10~0.24 | α 0.44~0.58 | **落在空白区** ⇒ 用户看到的"中间一块灰矩形" |

**改法（S4）**：把画笔从整层下移到**只包「进度行 + 控件行 + 底留白」的内层 Column**
（约 74dp），层顶 44dp 改为纯透明。

| 项 | 改前 | 改后 |
|---|---|---|
| 画笔挂载容器 | 外层 Column（`.height(层高)`） | 内层 Column（`.fillMaxWidth()`） |
| 覆盖高度 | 118 / 126 dp | **86 / 94 dp**（−32/−32） |
| 画面可见面积 | 基准 | **+约 37%**（74/118） |
| 渐变停靠 | 5 档 (0/0.10/0.24/0.50/1) | 4 档 (0/**0.58**/0.12→0.88/0.30→0.88/1) |

**期间被守卫拦下的两个真实问题（都修了，不是放宽）**：
1. 第一版渐变 `0→0.18 才爬满` 时，进度轨道在**盒顶**（f≈0.16）只有 α=0.39
   ⇒ 白 42% 轨道 **1.60:1**（门槛 3:1），亮画面上轨道看不见。
   → 改为 0.12 处即达平台 0.88，轨道吃满实底。
2. 原有的「W59 防恒真」自检要求"几何取样 ≠ 末端值代入"，但新形态下轨道**有意**
   落在平坦段，两者按设计就相等。→ 重写自检为"把轨道挪到盒顶必须显著变暗"，
   目的（防恒真）保留，只是换了能分辨的度量。

### 2.2 首页模糊 —— 卡片上轮已删，本轮删顶栏

`HomeVideoPage` 玻璃上轮已归零。本轮处理最后一处：`HomeScreen` 顶栏三挂载
（`hazeSource` / `layerBackdrop` / `glassEffect`）。

**改法（S5）**：加 `homeTopBarGlassEnabled()` 门控 —— **只在 `GlassMaterial.LIQUID` 时挂**
（用户显式 opt-in 的高成本特效）。默认 `FROSTED` 档不再挂。

- 源侧（`hazeSource` / `layerBackdrop`）与消费侧（`topGlassOn`）**同源门控**：
  只关消费不关源的话，录制照样每帧跑、性能一分不省。
- 观感不是"变丑"：`isIOS` 本来就有半透明纯色底分支（alpha 0.85/0.92），零采样成本。
- 收益：首页滚动期不再有第二份全屏离屏录制。

### 2.3 同类问题：Tab 排"胶囊套胶囊"（S6）

`FilledTabRow` 的 Material 分支此前**每个 Tab 都是一颗 `Card`**（未选中 `Color.Transparent`），
Card 自带轮廓/高度/涟漪裁剪 ⇒ 一排读作"五颗按钮挤在一条里"。

### 为什么"关闭后保留按压反馈"是结构性保证

形变由**两个独立分量**驱动，不是 if 分支补丁：
- `press`（0..1）：按下即涨、抬手即落 —— 门控只看 `enabled`，**永不受用户开关影响**；
- `position`（Offset）：手指位置追踪 —— 只有它被 `dragEnabled && globalDragFeedbackEnabled` 门控。

```kotlin
val effectiveDragEnabled = dragEnabled && LocalThemeConfig.current.globalDragFeedbackEnabled
// press 动画：无条件启动
pressJob = scope.launch { press.animateTo(1f, appPressHighlightPressSpec()) }
// position 追踪：只在 effectiveDragEnabled 时更新
if (effectiveDragEnabled) { positionJob = scope.launch { position.snapTo(change.position) } }
```

### 形变公式（照搬上游）

```kotlin
val angle = atan2(offset.y, offset.x)
translationX = minDimension * tanh(0.05f * offset.x / minDimension) * feedbackStrength  // 跟手，tanh 压缩
translationY = minDimension * tanh(0.05f * offset.y / minDimension) * feedbackStrength
scaleX = baseScale + dragScale * abs(cos(angle) * offset.x / maxDimension) * (width/height).coerceAtMost(1f)
scaleY = baseScale + dragScale * abs(sin(angle) * offset.y / maxDimension) * (height/width).coerceAtMost(1f)
```

`baseScale = 1 + expansionPx/height * press`（按压膨胀，4dp 量），
`dragScale * abs(cos/sin(angle) * offset)` = 沿受力方向拉伸。

光斑：SDK 33+ 用 `RuntimeShader` smoothstep，低版本降级白 25% `BlendMode.Plus`。

## 四、第 4 条：设置页太老

用户原话：「设置页ui太老，不符合现代审美，参考bilipai的设置风格」。

**代码里"老"的具体来源（不是印象）**：`SettingItem.kt` 的 `SettingCategory` 图标是
`Box(48.dp).background(iconContainerColor, CircleShape)` —— Material 2 时代的
"一大颗彩色圆片"。副作用不只是观感：
- 每行文字起点被推到 **64dp**，一屏只放得下 7 行；
- 同屏十几颗彩色圆片互相抢注意力，读作"玩具面板"。

**改法（S3）**：去掉色块，改为**单色语义图标**（24dp 图标 + 32dp 布局槽），
与上游 `rememberSettingsSemanticIcon` 同款形态。文字起点 64dp → 48dp。

保留 `iconContainerColor` 参数（标 `@Suppress` + 注释说明已废弃）：11 个设置页
大量传它，删参数会波及全部调用点且零收益 ⇒ 保留让迁移可分批次。

`CapsuleGroup` 的 iOS Inset Grouped 能力（hairline 分隔线 + 左缩进 56dp）**原本就有**，
本轮未动。
