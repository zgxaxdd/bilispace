## 2. NX-11：那条 CI 命令到底怎么了（本批的机制修正）

**实测（Gradle 9.6，本地）**：

```
先把两任务跑成已执行状态：
  > Task :infra:player:testDebugUnitTest UP-TO-DATE
  > Task :core:rank:testDebugUnitTest            ← 执行

A B --rerun  →  :infra:player UP-TO-DATE      :core:rank 执行
B A --rerun  →  :core:rank    UP-TO-DATE      :infra:player 执行   ← 反序即翻转
```

→ **W22 仍然成立，且结论更精确**：不是"`--rerun` 被静默丢弃"，而是**它只给命令行的最后一个任务**。
旧 CI 写法 `:infra:player :core:rank :feature:video :app --rerun` 里，**真正复跑的只有 `:app`**。

**修法**（两道，缺一不可）：

1. **逐模块单任务调用**（`--rerun` 才会生效）；不改成 `--rerun-tasks`（连编译一起重跑，PR 时长暴涨）。
2. **自己校验任务真的执行了**：日志里必须是裸 `> Task :x:testDebugUnitTest`，出现
   `UP-TO-DATE / FROM-CACHE / SKIPPED / NO-SOURCE` 立即 `::error::` 并失败。
   只靠注释约束不住未来 —— 这一条让 W22 那类行为变化**当场暴露**。

**模块清单口径**：只收**含"扫源码型守卫"的模块**（判据写进注释：
`grep -rl -E "settings\.gradle\.kts|walkTopDown\(\)" <module>/src/test`）。
旧清单漏了 `:core:designsystem` —— 而它正是 PT 批次红了 5 条的模块。补入
`core:feed / core:playback / core:settings / core:common / feature:settings / infra:coldstart`。

**代价（如实登记）**：全量逐模块真跑 ≈ **17 分钟**（含 `:app` 4m01 与 `:core:designsystem` 7m24），
而旧写法"看起来 4 分钟"其实是只有 `:app` 在真跑。这是**用时长换门禁的真实性**，取舍已写进 workflow 注释。
CI 上的实际时长需在一次真实 PR 里确认（L4-96）。
