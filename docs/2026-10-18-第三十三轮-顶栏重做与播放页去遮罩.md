## 第 1 条：顶栏重做

### 根因（我上一轮改错的，先认下来）

上一轮为了修「整体滑动 + 轮廓没隐藏」，我把顶栏拆成**两层**：

```
Box(.clipToBounds())          // ← 固定裁剪窗，底色/玻璃挂在这一层
  Column(.offset { -offset }) // ← 只有内容在这层移动
```

后果正如用户描述：**底色被钉死在 y=0**，内容滑走了，那条不透明的片还在屏幕顶端，
永远不会消失。所以「文字能隐藏、顶栏不能隐藏」。

### 新结构：整条顶栏作为一个整体位移

```
Box(
  modifier = Modifier
    .graphicsLayer { translationY = -topBarOffsetPxProvider() }   // 底色 + 内容一起走
    .background(MaterialTheme.colorScheme.background, topBarShape)
    .statusBarsPadding()
)
```

三个结构性收益：

1. **能真正隐藏**：`offset` 达到顶栏实测高度时，整条（含底色与下角圆角）完全移出屏幕；
2. **滚动期零布局**：`graphicsLayer` 的 lambda 在**绘制阶段**执行，读 `offsetPx` 只让本节点
   重绘。旧版 `offset {}` 是**布局阶段**，每个滚动像素都触发一次顶栏重测量/重布局
   —— 而顶栏里有 `Card`、两个 `IconButton`、miuix `TabRow`，重布局比"平移一个已录好的
   图层"贵一个数量级；
3. **零采样**：顶栏不再有任何实时模糊。

### 减少性能消耗：整块删掉首页私有玻璃源

删掉的东西（不是收紧门控，是**删除**）：

| 符号 | 原作用 |
|---|---|
| `homeGlassState`（`HazeState`） | 首页私有 haze 源 |
| `homeLiquidBackdrop`（`rememberLayerBackdrop()`） | 首页私有 miuix 背板 |
| `homeGlassRefresher`（`GlassSourceRefresher`） | 驱动上面两者的**逐帧全屏离屏录制** |
| `homeHazeOn` / `homeLiquidOn` / `homeGlassOn` / `homeTopBarGlassEnabled()` | 四层门控 |
| `CompositionLocalProvider(LocalGlassHazeState / LocalGlassRefresher / LocalLiquidBackdrop)` | 向顶栏下发玻璃环境 |
| `HomeTopBar` 里的 `glassEffect(...)` / `glassFrameRefresh(...)` / `isGlassActive(...)` | 顶栏玻璃面 |

**为什么必须删、而不是继续收紧门控（这是我的判断失误，写下来免得重犯）**：
上一轮我把玻璃收进 `homeTopBarGlassEnabled()`（只在 `GlassMaterial.LIQUID` 挂），
以为省了性能。但用户设备是 `ui_style=IOS + glass_material=LIQUID`
（从 `files/datastore/app_settings.preferences_pb` 读出的权威值）⇒ **门控对他是恒真的**，
一行都没省。"收紧门控"在这种配置组合下**不能当作"省性能"交付**。

顺带删掉 `HomeTopBarScrollState` 里的 `isScrolling` 与 120ms 静默计时器：它们唯一的消费者
就是顶栏玻璃的 `isScrolling` 参数。消费者没了，这份状态就是纯开销 —— 而且每个滚动位移
都要**取消一个 Job 再启动一个 Job**（延迟 120ms），一次快滑几十上百次。

### 减少顶栏区域

删掉 iOS 大标题（`iOSTypography.displayLarge` = 34sp，行高约 41dp + 上下内边距 ≈ 47dp）。
顶栏从「大标题 + 搜索行 + Tab 行」收成「搜索行 + Tab 行」两行。
页面分区名仍在 Tab 行里（选中的那颗胶囊就是它），信息没有丢。

底部内边距 `smPlus`(10) → `sm`(8)：大标题走了以后不需要那么厚的"玻璃厚度"了。

### 视觉对齐（第 4 条）

搜索胶囊 / 刷视频芯片 / 头像三件可点件：
- **同高**：搜索行 vertical padding 用 `BiliSpacing.sm`(8)，20dp 图标 + 16 = **36dp**；
  两颗圆形芯片用 `homeProfileAvatarSize`(38dp)。三者视觉高度对齐在同一中线。
- **同间距**：`Arrangement.spacedBy(BiliSpacing.sm)`（旧版紧贴无间距）。
- **同栅格**：左右 `BiliSpacing.md`(12dp)，与底栏 Dock 同列。
- 顺带：`onNavigateToProfile` 的 `IconButton` 原先 modifier 只有 `.semantics{}`，
  现在补 `.appElasticPress(visualSize = homeProfileAvatarSize)`。

### 可读性怎么保（删了遮罩不等于不要对比度）

三来源模型，每个都从源码解析、可独立验证：

1. **可点件自带底盘**：`PlayerChipScrim = Color.Black.copy(alpha = 0.58f)`，
   底与图标**同尺寸** ⇒ 图标处有效 α 恒等于该底 α，与层高/画幅无关
   ⇒ `whiteTextOnBlackScrimOverWhiteFrame(0.58) ≥ 4.5`（AA 正文）。
2. **信息文字（不可点）靠投影**：`PlayerInfoTextShadow = Shadow(Black 0.55f, blurRadius = 6f)`，
   经 `playerInfoStyle(base)` 挂到标题 / UP 名 / 话题 / 合集 / 时间 / 顶栏 meta 上。
   测试只做**结构断言**（必须真挂在 `TextStyle.shadow` 上、必须真接进每个信息 Text），
   **不**假装投影等于某个 α 的实底（那是自欺）。
3. **轨道靠自己的暗槽**：`PlayerTrackBedScrim` 0.45 → **0.52**
   （遮罩删净后轨道背后变回纯白画面，0.45 只有 2.51:1，0.52 才 3.05:1 ⇒ 过非文本 3:1）。

## 守卫与测试

### 改写的守卫（不是放宽阈值，是改判据模型）

1. **`PlayerOverlayScrimContrastTest.kt`** 整篇重写（825 → 497 行，8 个测试）。
   旧判据的**全部**断言都建立在"文字坐在某条垂直渐变的某 fraction 处"上；渐变删了以后

   "渐变达标 ⇒ 全绿"；新模型要求三个来源各自达标、且互相不能冒充。

3. **`GlassMountRegistryTest`**：删除 HomeScreen 三条登记（`hazeSource` 284 /
