# 卡片动态取色 · 上游同步与修复 · 任务书

> 起因：用户反馈「推荐页卡片简介部分的颜色提取与 BiliPai 不一样，许多卡片提取颜色有问题，或者没有提取色」。
>
> **本任务书的调研部分已逐行核实，不是推测。** 每个结论都给了文件:行号。
>
> **约束：没有 USB、没有设备。** 全部验收靠「编译 + JVM 单测 + 静态断言」。
> 凡涉及观感的改动，**只做可回退实现 + 数值证明 + 待验证清单，不改默认开关**。

---

## 一、调研结论

### 1.1 取色算法**与上游完全一致** —— 不是 bug

逐行对比 `VideoCardCoverColorStore`：

| 参数 | 上游 | BBSpace | |
|---|---|---|---|
| `resizeBitmapArea` | `48*48` | `48*48` | ✅ 同 |
| `maximumColorCount` | `16` | `16` | ✅ 同 |
| `clearFilters()` | 有 | 有 | ✅ 同 |
| HSV 过滤 | `hsv[1]<0.08 \|\| hsv[2]<0.08 \|\| hsv[2]>0.96` | 完全相同 | ✅ 同 |
| 选取 | `maxByOrNull { population }` | 完全相同 | ✅ 同 |
| 缓存命中同步回调 | 有 | 有 | ✅ 同 |
| HARDWARE→ARGB_8888 | 有 | 有 | ✅ 同 |

**上游 105 行、BBSpace 136 行，多出的 31 行全是注释。**

### 1.2 主因①：**染色强度被主动调低**（提交 `d70fcce0`，今天 22:37）

| 参数 | 上游 | BBSpace 现 | 变化 |
|---|---|---|---|
| `glassTransparency` 浅色 | 0.34 | **0.20** | ↓41% |
| `glassTransparency` 深色 | 0.38 | **0.28** | ↓26% |
| `blendFraction` 浅色 | 0.75 | **0.58** | ↓23% |
| `blendFraction` 深色 | 0.85 | **0.72** | ↓15% |
| `glowAlpha` 浅色 | 0.38 | **0.22** | ↓42% |
| `glowAlpha` 深色 | 0.48 | **0.34** | ↓29% |
| `borderAlpha` 浅色 | 0.45 | **0.32** | ↓29% |
| `borderAlpha` 深色 | 0.30 | **0.24** | ↓20% |

**最终色偏**（浅色、有封面色）：
- 上游：`lerp(底, 色, 0.75) × 0.34` → 相对背景色偏 ≈ **0.255**
- BBSpace：`lerp(底, 色, 0.58) × 0.20` → 相对背景色偏 ≈ **0.116**

→ **BBSpace 的染色可见度只有上游的 45%。** 这直接对应"颜色提取有问题"。

该提交的理由（原文）：「原值在双列信息流上会让每张卡的信息区呈现一块高饱和色带……整屏读作拼色块，是当前界面最显旧的一处」。**它是对着真机截图有意改的**，与用户当前诉求直接冲突。

### 1.3 主因②：缺壁纸色板链路

上游取色的**主来源是壁纸**，封面只是回退：

```kotlin
// 上游 VideoCardAdaptiveTintPolicy.kt:73-76
internal fun shouldUseCoverTintForCard(wallpaperTintEnabled, coverTint) =
    !wallpaperTintEnabled && coverTint != null && coverTint.alpha > 0f
```

BBSpace 缺失：`WallpaperPaletteStore`(上游 168 行)、`HomeGlassVisualPolicy`(511 行)、
`LocalWallpaperPalette`、`interpolateWallpaperColor`（Y 轴插值）、`SamplingRegion`。

### 1.4 主因③：缓存键策略不同

| | 上游 | BBSpace |
|---|---|---|
| 取色键 | `resolveVideoCardCoverCacheKey` → `cover_{bvid}_n`(+`cacheKeySuffix`) | `item.cover`（**原始 URL**） |
| 传给 Coil | ✅ `memoryCacheKey` / `diskCacheKey` / `placeholderMemoryCacheKey` | ❌ **没传** |

上游键与 Coil 缓存键**同源**；BBSpace 不同源。

### 1.5 ⚠️ 一个必须澄清的前提（影响范围判断）

**BiliPai 的"壁纸"是 App 自定义的首页背景壁纸，不是系统 Monet。**

- BBSpace 设置页的「动态取色」= Android 12 系统 Monet（`useDynamicColor`）—— **两回事**
- BBSpace **完全没有**自定义壁纸功能（全仓 `Wallpaper` 只出现在注释与这条设置文案里）
- 上游 `HomeScreen.kt:2161`：`wallpaperTintEnabled = homeWallpaperBackdropAppearance.visible`
  → **只在开了自定义壁纸背景时才用壁纸染色**

**推论**：在 BBSpace 里，即使移植完整壁纸系统，**默认也是关的**，卡片仍走封面色。
所以"与 BiliPai 不一样"的**主因是 1.2（强度）**，不是缺壁纸。

### 1.6 次要：`LocalHomeCardDynamicTintEnabled` 无人 `provides`

上游在 `AppNavigation.kt:554` 与 `VideoActivity.kt:250` 显式 provide；BBSpace 只用默认值 `true`。

## 二、实施计划

### 阶段 A ⭐ 染色强度调回折中值（最高收益、最小改动）

`core/designsystem/.../color/VideoCardAdaptiveTintPolicy.kt`：

| 参数 | 现值 | 改为 |
|---|---|---|
| `glassTransparency` 浅 / 深 | 0.20 / 0.28 | **0.28 / 0.34** |
| `blendFraction` 浅 / 深 | 0.58 / 0.72 | **0.68 / 0.80** |
| `glowAlpha` 浅 / 深 | 0.22 / 0.34 | **0.30 / 0.42** |
| `borderAlpha` 浅 / 深 | 0.32 / 0.24 | **0.40 / 0.28** |
| `borderBlendFraction` | 0.40 / 0.50 | 不变（与上游同） |
| data saver 档 | 0.70 / 0.65 | 不变（与上游同） |

**为什么是这组值**：取上游与现值的中间偏上，兼顾"看得出颜色"与"不拼色块"。

**验收**：
- 现有 15 条单测钉的是**关系**（半透明 / 光晕>0 / 深色更强 / data saver 更不透明）不是数值
  → 调参**不会**假绿
- **新增数值断言**把这组折中值钉住，防止再次被无声改掉
- 断言"染色可见度（blend×alpha）不低于某下限"，把"太淡"这件事变成可测的

### 阶段 B 缓存键与 Coil 对齐

1. 新增 `resolveVideoCardCoverCacheKey(identity, useLowQualityCover)` → `cover_{identity}_n`
   （identity 优先 `bvid`，回退 `cover`，再回退 `aid_cid_titleHash` —— 照抄上游 `VideoCard.kt:180-192`）
2. `rememberBiliImageRequest` 增加可选 `memoryCacheKey` / `diskCacheKey` 形参
3. 取色键改用同一函数 → **取色键与 Coil 缓存键同源**

**验收**：
- JVM 单测：断言"取色键 == Coil 请求键"（同源）
- JVM 单测：identity 回退链（bvid 空 → cover → aid/cid/title）
- 结构断言：卡片请求必须传 `memoryCacheKey`

### 阶段 C 移植壁纸色板（**仅系统壁纸那一路**）

1. 移植 `WallpaperPaletteStore`，**只保留**：
   - `extractSystemWallpaperPalette`（`WallpaperManager.getWallpaperColors(FLAG_SYSTEM)`）
   - `createDefaultThemePalette`（降级）
   - `currentPalette: StateFlow` + LRU(8) + `clearCache`
   - **不移植** `extractWallpaperPaletteFromUri`（BBSpace 无自定义壁纸 URI）
2. 移植 `WallpaperPalette` 数据结构 + `LocalWallpaperPalette` + `interpolateWallpaperColor`（纯函数）
3. `resolveVideoCardAmbientDrawSpec` 增加 `wallpaperPalette: WallpaperPalette?` 与 `yFraction: Float`
   （**新形参放末尾并给默认值**，避免破坏现有调用点与测试）
4. 卡片计算 `yFraction = rootTop / screenHeight`，读 `LocalWallpaperPalette`
5. **新增设置开关**「卡片跟随系统壁纸取色」，**默认关**

**为什么默认关**：BBSpace 没有壁纸背景功能，默认开会与 BiliPai 观感不一致；
且这是新增能力，不应改变现有默认行为。

**验收**：
- 纯函数 JVM 单测：插值边界（0 / 1 / 越界钳制）、stops 空 / 单元素、色板为 null 的降级
- 结构断言：设置开关默认 `false`
- 单测：`wallpaperTintEnabled=false` 时**行为与现在完全一致**（回归保护）

### 阶段 D `LocalHomeCardDynamicTintEnabled` 显式 provide

在 `AppNavHost` 与 `VideoDetailActivity` 入口显式 provide（与上游一致），默认仍 `true`。

**验收**：结构断言两个入口都有 provide。

### 阶段 E 诊断与文档

1. `BbDynamicTint` debug 日志**补"未取到色"分支**（当前只在成功时打，失败无痕迹 —— 这正是用户报"没有提取色"却查不到原因的原因）
2. 写 `docs/2026-09-22-卡片动态取色-上游对照与修复.md`：调研表 + 修复清单 + **待设备验证清单**

## 三、验收标准

| 项 | 方式 |
|---|---|
| 编译 | `:app:assembleDebug` BUILD SUCCESSFUL，无新增 `e:` |
| 单测 | `testDebugUnitTest` 全绿（当前 135，新增若干） |
| 新断言**会咬人** | 故意破坏一次，确认 FAILED |
| 强度值被钉住 | 数值断言 + 可见度下限断言 |
| 键同源 | 单测断言取色键 == Coil 键 |
| 壁纸开关默认关 | 结构断言 |
| **不改其它默认行为** | `git diff` 证明 |
| **不声称观感/性能数字** | 无设备，测不了 |

## 四、明确不做

- ❌ **移植 App 自定义壁纸背景功能**（`HomeWallpaperEffectMode`/`HomeWallpaperEffectScope`/
  `WallpaperMedia`/`isVideoWallpaper`/`HomeWallpaperBackdrop` + 设置页）
  —— 那是一个**新功能**，不是取色修复；且它默认关，不影响当前问题
- ❌ 把任何开关默认值改成开
- ❌ 声称观感改善（无设备）

## 五、风险与待验证

| # | 风险 / 待验证 | 说明 |
|---|---|---|
| 1 | **阶段 A 与另一个 agent 的"避免拼色块"决定冲突** | 折中值是妥协，需有设备时微调 |
| 2 | **阶段 C 默认关**，插上设备也看不到变化 | 除非手动开设置。若要默认开需明确指示 |
| 3 | 系统壁纸色在 ColorOS 上**可能取不到** | 已写降级路径（`createDefaultThemePalette`），但真机行为待验 |
| 4 | 染色强度的**观感**（太淡/太艳） | 待设备截图对比 |
| 5 | 壁纸色与封面色**谁该优先**的观感 | 当前按上游逻辑（壁纸开时壁纸优先），待验 |

## 六、铁律（本仓库真实事故）

1. **绝不用 PowerShell 改文件内容** —— 曾把中文写成乱码，仍是合法 UTF-8、能编译
2. pwsh 的 `cd` 不跨调用保持；`[System.IO.File]::*` 用**绝对路径**
3. 结构断言扫描器**跳过注释行和 import 行**
4. 每个断言先确认**目标文件真读到了**（防假绿）
5. 改完测试**验证它会咬人**
6. 棘轮上限只许减，调大要写理由
7. 每完成一项就 commit
