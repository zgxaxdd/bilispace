# 卡片动态取色 · 上游对照与修复（2026-09-22）

> 起因：用户反馈「推荐页卡片简介部分的颜色提取与 BiliPai 不一样，许多卡片提取颜色有问题，
> 或者没有提取色」。
>
> **约束**：本机无 USB、无设备。所有结论来自**逐行代码对比**与**JVM 单测**，
> 观感类结论一律标注「待设备验证」。

---

## 一、调研：三个根因（都已逐行核实）

### 1.1 取色算法与上游**完全一致** —— 不是 bug

| 参数 | 上游 BiliPai | BBSpace |
|---|---|---|
| `resizeBitmapArea` | `48*48` | `48*48` |
| `maximumColorCount` | `16` | `16` |
| `clearFilters()` | 有 | 有 |
| HSV 过滤 | `hsv[1]<0.08 \|\| hsv[2]<0.08 \|\| hsv[2]>0.96` | 完全相同 |
| 选取 | `maxByOrNull { population }` | 完全相同 |
| 缓存命中同步回调 | 有 | 有 |
| HARDWARE→ARGB_8888 | 有 | 有 |

上游 105 行、BBSpace 136 行，**多出的 31 行全是注释**。

**结论：算法层面没有差异，"取色不准"不来自算法。**

### 1.2 根因①：染色强度被主动调低

提交 `d70fcce0`（2026-09-22 22:37，另一个 agent 对着真机截图改的）：

| 参数 | 上游 | 被下调后 | 变化 |
|---|---|---|---|
| `glassTransparency` 浅 / 深 | 0.34 / 0.38 | 0.20 / 0.28 | ↓41% / ↓26% |
| `blendFraction` 浅 / 深 | 0.75 / 0.85 | 0.58 / 0.72 | ↓23% / ↓15% |
| `glowAlpha` 浅 / 深 | 0.38 / 0.48 | 0.22 / 0.34 | ↓42% / ↓29% |
| `borderAlpha` 浅 / 深 | 0.45 / 0.30 | 0.32 / 0.24 | ↓29% / ↓20% |

**染色可见度**（`blend × alpha`，浅色有封面色）：
- 上游：`0.75 × 0.34` = **0.255**
- 被下调后：`0.58 × 0.20` = **0.116**（只剩 45%）

该提交的理由（原文）：「原值在双列信息流上会让每张卡的信息区呈现一块高饱和色带……
整屏读作拼色块，是当前界面最显旧的一处」。

**这与用户诉求直接冲突**：一个方向要"整屏统一"，另一个方向要"看得出颜色"。

### 1.3 根因②：缓存键与 Coil 不同源

| | 上游 | BBSpace（修复前） |
|---|---|---|
| 取色键 | `resolveVideoCardCoverCacheKey` → `cover_{bvid}_n`(+`cacheKeySuffix`) | `item.cover`（**原始 URL**） |
| 是否传给 Coil | ✅ `memoryCacheKey` / `diskCacheKey` / `placeholderMemoryCacheKey` | ❌ **没传** |

**症状完全静默**：算过色的封面查不到、查得到的没算过 → 表现成"很多卡片没取色"，
且**没有任何报错**。

### 1.4 根因③：缺壁纸色板链路

上游取色的**主来源是壁纸**，封面只是回退：

```kotlin
// 上游 VideoCardAdaptiveTintPolicy.kt:73-76
internal fun shouldUseCoverTintForCard(wallpaperTintEnabled, coverTint) =
    !wallpaperTintEnabled && coverTint != null && coverTint.alpha > 0f
```

BBSpace 此前缺失：`WallpaperPaletteStore`、`HomeGlassVisualPolicy`、
`LocalWallpaperPalette`、`interpolateWallpaperColor`。

### 1.5 一个重要澄清（避免误判范围）

**BiliPai 的"壁纸"是 App 自定义的首页背景壁纸，不是系统 Monet。**

- BBSpace 设置页的「动态取色」= Android 12 系统 Monet（`useDynamicColor`）—— **两回事**
- BBSpace **完全没有**自定义壁纸功能
- 上游 `HomeScreen.kt:2161`：`wallpaperTintEnabled = homeWallpaperBackdropAppearance.visible`
  → 只在开了自定义壁纸背景时才用壁纸染色

**因此"与 BiliPai 不一样"的主因是 §1.2（强度），不是缺壁纸。**

## 二、修复清单

### 2.1 染色强度调回折中值（`58627c5d`）

| 参数 | 被下调后 | 本次 |
|---|---|---|
| `glassTransparency` 浅 / 深 | 0.20 / 0.28 | **0.28 / 0.34** |
| `blendFraction` 浅 / 深 | 0.58 / 0.72 | **0.68 / 0.80** |
| `glowAlpha` 浅 / 深 | 0.22 / 0.34 | **0.30 / 0.42** |
| `borderAlpha` 浅 / 深 | 0.32 / 0.24 | **0.40 / 0.28** |

可见度：0.116 → **0.190**（上游 0.255 的 75%）。

**关键补强**：现有 15 条测试**只钉关系不钉数值**，所以两轮相反方向的改动都没报警。
新增 4 条数值守卫，判据是「色偏 × alpha」：
- 浅/深可见度 **≥0.15**（实测能挡住 0.102 那版）
- 可见度 **≤0.45**（反向守卫，防退化成纯色板）
- 光晕与底色同阶（防"只调底色忘了光晕"）

**已验证会咬人**：改回被下调的值 → 3 条 FAILED。

### 2.2 缓存键三处同源（`5ff7bbe9`）

1. 新增 `resolveCoverCacheKey(identity, useLargeCover)` → `cover_{identity}_{l|n}`
   - 带质量档：单双列请求不同尺寸位图，共用键会让小图命中大图槽位
   - 空 identity 返回**空串**（而非 `cover__n`）—— 后者会让所有未知视频共用一把键、互相串色
2. `BiliAsyncImage` / `CoverImage` 增加 `cacheKey`，同时设 memory + disk key
3. `HomeVideoPage` 取色键改用 `item.actionKey`（列表稳定键）
4. **预加载也带同一个键** —— 卡片显式指定键后 Coil 不再按 URL 派生，
   预加载不跟上就是两个键、静默白做（等于把第一阶段修好的事换个地方再犯）。
   为此把预加载列表从 `List<String>` 改成 `List<CoverPreloadEntry>(url + cacheKey)`，
   **用类型把两者绑在一起**。

新增 `CoverCacheKeyTest` 12 条（6 行为 + 5 结构 + 1 防假绿）。
**已验证会咬人**。

### 2.3 接入系统壁纸色板（`a000dffd`）

1. `WallpaperPaletteStore`（**裁剪版**）：`WallpaperManager.getWallpaperColors(FLAG_SYSTEM)`
   - **不移植** `extractWallpaperPaletteFromUri` —— 它依赖 BBSpace 没有的自定义壁纸功能
   - 取不到时退回 `createDefaultThemePalette`（数值照抄上游），**不返回 null**
2. `WallpaperPalette` 数据类 + `LocalWallpaperPalette` + `interpolateWallpaperColor`（纯函数）
3. `resolveVideoCardAmbientDrawSpec` 增加 `wallpaperPalette` / `yFraction`（末尾形参 + 默认值 → 回归安全）
   - 壁纸路直接铺插值后的真实壁纸色，**不与容器底色混合**（混合会冲淡成灰白）
   - 壁纸开着但调色板未就绪 → 保持中性表面，**不退回封面色**（否则先闪一下再跳变）
   - 微光/描边仍只跟封面色走（壁纸路没有"封面边缘"概念）
4. 设置项「卡片跟随壁纸取色」，**默认开**
5. `HomeScreen` 加载并 provide；卡片读它并算 `yFraction`

### 2.4 诊断补强（本次）

`extractColorAsync` 原实现失败时**静默 return**，导致用户报"没有取色"时现场没有痕迹。
新增可选 `onExtractionFailed` 回调，区分三类失败：
- `blank cache key`（键算错 —— 与本次修的两个 bug 同类）
- `bitmap recycled`
- `palette returned no swatch (config=... WxH)`

debug 构建下打 `BbDynamicTint` 标签的 warning。

## 三、踩到的坑（写给后人）

### 3.1 `LocalWallpaperPalette` provide 错了层级

第一版把它和玻璃那几个一起 provide 在**顶栏那层**，但 `HomeVideoPage` 在 pager 里、
**位于那个 provider 之前** —— 卡片读到的永远是 null，整条链路没接上，
**且没有任何报错**（`staticCompositionLocalOf` 默认值就是 null）。

改为单开一层只负责调色板，作用域覆盖 pager 与顶栏。

**教训**：provide 一个 CompositionLocal 后，要确认**消费者真的在它的作用域内**，
不能只看"我 provide 了"。

### 3.2 本文件记下的三次"两边各算一个键"

1. 预加载传未解析的 `item.cover`（第一阶段修）
2. 取色键用原始 URL、Coil 按解析后 URL 派生（本次修）
3. 卡片显式指定键后预加载没跟上（本次一并修）

三次都是**同一个错误形状**：两处独立计算同一个键。所以第三次改用**类型**把
url 与 cacheKey 绑成 `CoverPreloadEntry`，而不是靠人记得同步。

## 四、待设备验证清单

> 本机无 USB。以下每条都需要真机确认，**不要当作已完成**。

| # | 验证什么 | 操作步骤 | 预期信号 | 失败长什么样 |
|---|---|---|---|---|
| 1 | **壁纸色能否取到** | 装 debug 包，看 logcat `BbDynamicTint` | ColorOS 上 `getWallpaperColors` 返回非空 → 卡片染的是壁纸主色 | 若取不到 → 走 `createDefaultThemePalette`（一组紫），卡片会**普遍偏紫**，与壁纸无关 |
| 2 | **染色强度观感** | 浅色/深色各截图，与 BiliPai 同屏对比 | 信息区看得出与封面同源，但不成"色块" | 太淡（像没上色）→ 上调 `glassTransparency`；太艳（拼色块）→ 下调 |
| 3 | **壁纸色 vs 封面色谁更协调** | 开/关「卡片跟随壁纸取色」各截图 | 壁纸路应更"整屏统一" | 若壁纸路让所有卡同色、失去卡片个性 → 考虑默认关 |
| 4 | **yFraction 插值是否真的流动** | 慢速滚动首页，看卡片信息区颜色是否随位置变化 | 顶部卡片偏 topColor、底部偏 bottomColor，滚动时平滑过渡 | 若所有卡同色 → 插值没生效（查 `onGloballyPositioned` 的 `positionInParent` 是否拿到正确值） |
| 5 | **缓存键同源是否真的生效** | 滚动一段后回到已看过的卡 | 颜色立刻在（命中取色缓存），不重新算 | 若回来颜色"闪一下才出现" → 键仍不同源 |
| 6 | **诊断日志是否够用** | 故意断网/用损坏封面 | 出现 `extraction FAILED reason=...` | 若完全没有该日志 → 说明 `onImageLoaded` 根本没触发（那是另一个问题） |
| 7 | **性能** | 冷启动后滚动 8 轮，`perf-baseline.ps1` | jank 不劣于 0.21% | 若明显变差 → 查 `onGloballyPositioned` 是否每帧写 state 导致额外失效 |
