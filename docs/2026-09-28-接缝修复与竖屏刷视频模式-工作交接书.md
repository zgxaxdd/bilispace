## 4. 真机观察点与已知风险

- **窗口动画 vs ColorOS 动效等级**：`persist.sys.oplus.anim_level` 低档机型上窗口动画时长可能
  被系统缩放；观感不对先调 `app/src/main/res/anim/window_*.xml` 的 duration。
- **无缝回退率**：卡片/按钮注册失败（浮窗、分屏、系统拒绝）会落到统一窗口动画——这是设计行为，
  判定标准是"回退后的动画也体面且对称"，不是"必须无缝"。
- **story 流可能为空**（未登录/风控）：降级单视频全屏，属预期；若真机常态为空，查接口是否需要
  WBI 签名或登录态（BiliPai 未加，bbspace 亦未加）。
- **halo/spill 亮度**：深色底若读作"一条亮带"，调 `SEAM_HALO_PEAK_DARK`↓0.26、
  `SEAM_SPILL_PEAK_DARK`↑0.16，不动曲线。
- 极罕见：story 全屏期间被非 story 的 onNewIntent 打开 → 详情列表被全屏 pager 盖住（返回可退出，
  冷启动恢复）；不做专门处理（见 C5 §五）。

## 6. 踩过的坑（接手人必读）

1. **上一会话"编译通过"结论曾为假**：`androidx.compose.ui.graphics.Stroke` 无法解析（真实位置
   `androidx.compose.ui.graphics.drawscope.Stroke`，用 Gradle 缓存 aar 反查确认）。**一切以本轮
   构建输出为准，勿信历史结论。**
2. **countMatching 按行匹配**（VideoLogicGuardTest）：跨行正则永远 0；`BlendMode.Screen` 这类
   裸字面量断言会被注释污染——先 grep 实际计数再写断言（本轮 3 次断言/代码双向修正）。
3. **composable 体内禁止就地 `val xShape = RoundedCornerShape(...)`**（ListAllocationStructureTest
   全仓 0 容忍）——新形状一律文件级常量。
4. **rememberPagerState 会记住首次的 pageCount lambda**：动态页数必须
   `rememberUpdatedState(size)` 间接读，否则队列追加后 pager 页数不更新（"无限刷"静默失效）。
5. **上下滑翻页必须以 `requestedBvid`（pager 认定页）发请求**，不能拿 currentBvid 反向比较
   （取流完成前是旧值，快速往返会目标震荡）；迟到流的对齐以"用户所在页"为准。
6. **story 模式与 beginSwipeSession 互斥**：story 的锚点/队列由 `bootstrapStorySession` 全权负责
   （强制覆盖），VideoScreen 的会话接线在 `effectiveStoryMode` 下跳过——两条数据链同时跑会
   互相重置锚点。
7. **OplusViewSeamless**：锚点 View 必须 attach 到 window；`finishCurrentAnimation` 除滚动中断
   外不要调（打断系统合并动画，"can't reverse"）；本机（PLC110/ColorOS 16.0）`onAnimationEnd`
  **不送达**，阶段推进靠 `SeamlessTransitionState` 的 800ms 时长兜底（onStart/progress 正常）。
8. **dp 棘轮**：新代码一律 `BiliSpacing` token / `常量 * density`，写死 `N.dp` 会顶红
   DesignTokenLintTest（当前 16.dp≤176、8.dp≤150、总量≤980；本轮净减）。
9. 播放器手势与 pager 天然不冲突（放大态 pinchZoom 消费单指拖动，非放大态放行）——**不要**
   再加显式 scale 禁滑逻辑，会双份消费。
