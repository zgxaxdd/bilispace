## 0. 一句话目标与阅读指引

**目标**：把现有 `UiStyle.IOS` 从"一套换源的视觉 token"升级为"完整的 iOS 设计语言实现"——色彩层级、排版阶梯、几何、材质（液态玻璃）、动效曲线、控件语汇、系统融合七个维度全部对齐 iOS（以 iOS 26 / Liquid Glass 语汇为基准），同时保持 `UiStyle.MATERIAL` 档零回归。

**阅读指引**：
- §1 是**事实盘点**（现状 = 代码），任何"升级"都必须先看这一节；
- §2 是**差距分析**（每条给差距等级 P0/P1/P2）；
- §3 是**分阶段路线图**（A–E），每阶段含改动面（文件清单）、验收标准、风险；
- §4 说明如何与本仓既有的**棘轮/守卫测试**对接（不许靠肉眼维持）；
- §5 是**验收与真机走查清单**；§6 是边界（不做什么）；§7 是附录（令牌映射表 + 散点消费清单）。

## 1. 现状盘点（基于真实代码）

### 1.1 风格开关与分发链路

| 环节 | 位置 | 现状 |
|---|---|---|
| 风格枚举 | `core/designsystem/.../theme/ThemeConfig.kt:57-60` | `UiStyle { MATERIAL, IOS }` |
| 默认值 | `ThemeConfig.kt:34` | 默认 `MATERIAL`；注释明确"iOS 化覆盖全部 feature 模块，先作为可选项发布，真机走查干净后翻转默认值只改这一行" |
| 配色分发 | `theme/Theme.kt:136-141` | `IOS -> iOSColorScheme(darkTheme, config.seedColor)`（`iOSColor.kt:29`） |
| 排版分发 | `theme/Theme.kt:163-166` | `IOS -> iOSTypography(config.fontScale)`（`iOSTypography.kt:160`） |

| 风格广播 | `theme/Theme.kt:187` | `LocalUiStyle provides config.uiStyle` |
| 附属开关 | `ThemeConfig.kt:37-40` | `glassMaterial`（OFF/FROSTED/LIQUID，默认 FROSTED）、`glassStrength`（0.5–2.0），**挂在 iOS 风格上**，MATERIAL 档不生效且置灰 |

**关键事实**：iOS 风格不是"一个主题开关"，而是"令牌换源 + 21 处散点消费"。散点消费清单见 §7.2（`GlassEffect`、`BiliTopBar`、`CapsuleGroup`、`FilledTabRow`、`SearchCapsuleField`、`SettingItem`、`HomeScreen`、`LinkedBottomDock`、`AppNavHost`、各弹层 `shape` 分支等）。**这 21 处是本次升级的主要改造面，也是"看起来不像 iOS"的技术根源**：语汇决策散落在 feature 层，改一处只像一处。

| bodySmall | 13/18 | Light | Footnote |

**动效**（`theme/Animation.kt:12-28` `BiliAnimations`）：`short=100 / medium=200 / long=300 / extraLong=400 / morph=280`，`morphEasing` 为 Apple easeInOut `(0.42,0,0.58,1)`（:30），另有 `emphasized(0.2,0,0,1)` / `standard(0.4,0,0.2,1)`；`AnimationSpeed.OFF` → `reduceMotion=true`（位移/形变退化）。`NavTransitions.kt:28` 提供 6 种页面转场，默认 `SHARED_AXIS_X`（`ThemeConfig.kt:21`）。

**玻璃/材质**（`glass/` 目录）：

- 两条**互斥**录屏链（haze 源 / miuix 背板）与逐帧重录门控（`GlassRefresher.kt`、`ChromeBackdropSource.kt`）——本次升级**不重做**这条链，只在其上调整观感参数。

## 3. 升级路线图

> 原则：**令牌先行 → 组件收口 → 材质/动效 → 系统融合**。每阶段独立可验收、可回滚；不触碰无缝动画链（`seamless/` 目录）与播放链路。

### 阶段 A · 语汇收口与令牌补全（解决 G1/G2/G8）

**目标**：让 feature 层不再出现 `if (LocalUiStyle.current == UiStyle.IOS)`。

**改动面**：
1. `core/designsystem` 新增**风格语义层**：例如 `LocalUiStyle` 的替代消费方式——组件内部按风格分支（`FilledTabRow`、`SearchCapsuleField`、`SettingItem` 已是这么做的，作为范式），或引入 `UiStyleTokens`（形状/间距/材质按风格打包）。
2. 21 处散点（§7.2）逐条迁移：`shape = if (isIOS) … else …` 这类分支改为组件/令牌内部决策。**例外保留**：`HomeVideoPage.kt:338`（角标玻璃开关）与 `GlassEffect.kt:101,211`（玻璃生效门禁）属于材质门禁，应改为读 `GlassConfig` 而非 `UiStyle`。
3. 补齐缺失令牌：**6dp / 10dp 间距档**（现状 111/80 处字面量）、**分隔线（separator）**、**分组标题/脚注样式**、**次要文字角色分档**（primary/secondary/tertiary）。
4. 文本样式收口：消掉 `DesignTokenLintTest` 记账的 6 处 `typography.x.copy(...)`（改为角色样式 token）。

**验收**：`grep -r "LocalUiStyle.current == UiStyle.IOS"` 仅剩 designsystem 内部；`DesignTokenLintTest` 棘轮（内联 copy ≤6 → 0，新增 6/10dp 档位后字面量下降）；全量单测绿。
**风险**：形状/间距批量替换会牵动视觉（历史上"盲替换 dp 制造回归"的教训，见执行报告 §2-T5.4）——必须逐处人工核对语义，分多次提交。

### 阶段 B · 色彩与层级（解决 G2/G9）

**改动面**：`iOSColor.kt` 重排语义色板（一级/二级/三级文字、separator、fill、elevation 五档）、`ColorContrastTest` 按**角色分档**重写断言、`isPureBlack` 档的层次复核。
**决策项（需设计拍板）**：浅色 `onSurfaceVariant` 是否提到 AA（执行报告 §5-D3：0x99→约 0xB8 即 4.72:1，会明显改变全站次要文字深浅）。本阶段**只产出对照图与两版 token，不擅自翻默认值**。
**验收**：`ColorContrastTest` + `IOSColorSchemeTest` 全绿；真机深浅两套截图走查。

### 阶段 C · 控件与弹层语汇（解决 G4/G5/G7）

**改动面**（全部新增于 `core/designsystem/component`，feature 层只换调用）：
| 新组件 | iOS 规格要点 | 复用/改造基础 |
|---|---|---|
| `IOSActionSheet` | 顶部分组圆角 14、破坏性操作红、取消独立块、跟手下拉关闭 | `CommentEditorSheet`/各 sheet 的现有布局 |
| `IOSSlider` | 2dp 轨道 + 28dp 命中区 + 拖动放大滑块 | `VideoPlayerPane` 自绘进度条（`TrackGeometry`）可抽取 |
| `IOSPicker` / `IOSSegmentedControl` | 滚轮/分段，触感与 44pt 行高 | `FilledTabRow`（分段）已具备一半 |
| `IOSContextMenu` | 长按放大 + 菜单浮层 + 预览区 | `MoreMenuDialog`（`HomeVideoPage.kt:901`）改造 |
| `IOSAlert` | 居中 270pt 宽、圆角 14、按钮分隔线 | `AppUpdateDialog`/`InterestDialog` |
| Grouped Inset List | 分组标题/脚注/内缩分隔线/行高 44 | `CapsuleGroup` + `SettingItem` |

**弹层**：`BiliRadius.sheetTop` 已收口，本阶段补 **grabber**、自适应高度、下拉关闭的跟手回弹（复用 `BiliPullToRefreshBox` 的阻尼）。
**验收**：`AccessibilityStructureTest`（48dp/触控/描述）+ 新增视觉一致性巡检（T4.4 那类静态断言）；每个新组件附一张真机对照图。
**风险**：Material 控件替换成 iOS 控件会影响现有交互习惯——**新组件先只在 iOS 档启用**，MATERIAL 档继续用旧组件。

### 阶段 D · 材质与动效（解决 G3/G6）

**改动面**：
1. 玻璃层级按"信息层级"取材质：顶栏/浮层/控件分别映射 Thin/Regular/Thick（`GlassEffect.styleFor` 的三组常量改为按 `GlassSurfaceType` + 层级查表）；vibrancy 参数统一（现 `1.5` 仅 `LiquidBackdrop`/`playerControlGlass` 两处，值需对齐）。
2. 动效曲线 tween→spring 族：`BiliAnimations` 增加 `springDamping/Stiffness` 两组（iOS 语汇），`morph`/转场/控件动画统一取用；**遵守 `FrameBudgetLintTest`**：动画值只在绘制/布局期读（本轮已有正反例）。
3. 手势联动：返回手势与转场预测性返回（Android 16）的视觉衔接；下拉关闭 sheet 的跟手曲线与 iOS 一致。
**验收**：`FrameBudgetLintTest`/`GlassRecordChainStructureTest` 绿；真机对比录屏（转场逐帧对照）；**玻璃重算次数不得上升**（用本轮验证过的 `invalidateDrawCache` 打点法）。

### 阶段 E · 系统融合与收尾（解决 G10/G11）

状态栏/导航栏图标色逐场景校准、圆角屏安全边距、键盘避让、动态字体（`fontScale`/`uiScale` 已有，需全页面回归）、VoiceOver 顺序、触控 48dp 全覆盖（解开 D4 冻结的 3 处）、预测性返回接入。

## 4. 与既有守卫/棘轮体系的对接

| 守卫 | 现状 | 本方案的扩展 |

## 5. 验收与真机走查清单

1. **风格切换**：MATERIAL ↔ IOS 切换 20 次无闪变、无状态丢失（主题镜像链路已就位）；
2. **逐页走查**（每页 iOS/MATERIAL/深浅 四象限截图）：首页信息流、视频详情、播放页（全屏/半屏）、搜索、空间、动态、评论、设置、下载、直播；
3. **控件走查**：开关/分段/滑杆/弹层/动作面板/警告框，含触感与命中区（48dp）；
4. **动效走查**：页面转场、返回手势、sheet 下拉、卡片展开（无缝与回退两路径）、胶囊/底栏；
5. **深色/纯黑**：玻璃在纯黑上的层次、文字对比度（按角色分档）；
6. **无障碍**：动态字体最大档布局不破、VoiceOver 顺序、`reduceMotion` 全生效；
7. **性能**：首页滚动/播放页暂停帧数/内存（沿用 `docs/performance-baseline.md` 与 §10 实测口径），**玻璃重算次数不升**。

## 6. 边界（本方案明确不做）

- 不改业务功能与数据链路（Repository/ViewModel/播放/下载）；
- 不重做无缝动画链（`seamless/` 目录的 OplusViewSeamless / CoverExpand / 位图缓存）——本次只在回退动画观感上继续打磨（已列 Bug ② 的 B 项）；
- 不翻转 `uiStyle` 默认值（等真机走查干净后"只改 `ThemeConfig.kt:34` 一行"，注释已预留）；
- 不做全局 dp 字面量盲替换（教训见执行报告 §2-T5.4）；
