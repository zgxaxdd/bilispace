## 分三类看这 14 个

### A 类：三态由统一网格持有，不该再叠一张 StateMessageCard（**不改**）
`ListenHomePage`、`HomeVideoPage`（都走 `AdaptiveMediaGrid`）。
`AdaptiveMediaGrid` 已经内建"错误优先于空态"（S5 那次修的就是它把网络失败渲染成"暂无内容"），
外层再放一张状态卡会出现两层空态互相覆盖 —— 这类**看起来不一致其实是分层正确**。

### B 类：本地/静态列表，本来就没有加载与失败两种时刻（**不改**）
`SettingsScreen`、`AboutScreen`、`AppearanceSettingsScreen`、`FeedSettingsScreen`、
`PerformanceSettingsScreen`、`PrivacySettingsScreen`、`SponsorBlockSettingsScreen`、`ErrorLogScreen`、
`DownloadPlayerScreen`（播放控制页，列表是已下载分片）。
给它们补"加载态"就是**为了数字好看硬造状态**（同 W18 里"别为了棘轮凑 token"）。

### C 类：真有异步、值得走查确认的（**待真机逐屏看，别在这里断言**）
| 文件 | 疑点 |
|---|---|
| `ImConversationScreen` | 会话消息分页拉取失败时，界面有没有区分"没有更多消息"与"拉取失败" |
| `RelationScreen` | 关注/粉丝列表是异步的，失败态是否存在、错误优先于空态（S5 判据） |
| `SpaceScreen` | 个人主页整页是异步的，本文件三列全空 —— 状态可能由子 pane 持有，需要确认没有"谁都以为对方负责" |
| `PlaybackHistoryPane` | error 通道为否：读本地库失败时用户看到什么 |
| `DynamicDetailScreen` / `FavoriteScreen` / `InterestScreen` / `VideoDetailPage` | 有 StateMessageCard 但"空态判定"为否：确认它们的错误/加载分支真的可达（文本扫描看不到条件） |
