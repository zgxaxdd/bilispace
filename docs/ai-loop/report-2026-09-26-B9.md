## 收口的 5 处（4 个文件）

| 文件 | 位置 | 原缺陷 |
|---|---|---|
| `infra/crypto/TicketGenerator.kt` | `refreshInBackground` 外层 catch | 取消被记成"后台刷新 ticket 失败"的 warn 日志 |
| `infra/crypto/TicketGenerator.kt` | `refresh` 的重试循环 catch | 取消走进 `lastError` 分支 → 被记成 "Attempt N failed" 并继续下一轮（还会 `delay()`） |
| `infra/coldstart/ColdStartClient.kt` | `getColdStartData` catch | 取消打成"获取冷启动数据失败"的错误日志，`regionCodeCache` 留空 |
| `infra/network-grpc/GaiaReporter.kt` | `reportIfNeeded` catch | 取消打成"上报失败" |
| `app/AppInitializer.kt` | 播放器预热 `runCatching { playbackSession.prepare() }` | 今日无人取消它，但 warmup 一旦被改挂到可取消作用域，就会静默变成 "Player warmup failed" |

前三处是 `try/catch (e: Exception)` 形态，改法是**在宽 catch 之前加
`catch (e: CancellationException) { throw e }`**；后一处是 `runCatching` → `runCatchingCancellable`。
动手前先确认了 infra 各模块**已经**依赖 `:core:common`（`infra/*/build.gradle.kts` 实测），
所以不需要动依赖方向。

每处都按 B8 的教训逐个核过"是不是 ST-06b 那种反向案例"：这 5 处都没有
"操作已成功、只剩记账"的语义（`GaiaReporter` 的 `markUploaded` 在取消时不执行是可接受的 ——
下次冷启动重新上报，属遥测幂等范围），所以传播取消是对的。判断依据写进了各处的注释里。
