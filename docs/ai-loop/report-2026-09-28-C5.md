# 批次报告 · C5 · 2026-09-28 · 首页顶栏「刷视频模式」入口 + OPPO 无缝动画接入

**分区**：A-功能 P1｜承接 `report-2026-09-28-C4.md`。用户原话：「首页顶栏的布局中有一个单列大图和双列网格切换的功能，请把这个改为进入刷视频模式的功能，并做好进入动画的适配（接入 OPPO 的无缝动画）」，中途追加指示：「直接移植 BiliPai 的 StoryScreen 用 StoryRepository.getStoryFeed（短视频流接口）」。

## 一、对追加指示的核实与采纳结论

核查 BiliPai 源码发现一个关键事实：**BiliPai 的 StoryScreen（首页刷视频入口）实际用的是首页推荐流分页**
（`VideoRepository.getHomeVideos(idx)`，StoryViewModel:42/75），而 `StoryRepository.getStoryFeed`
（`GET x/v2/feed/index/story`，竖屏故事流）用在**详情页竖屏 overlay**（VideoDetailPortraitOverlayAdapter:149，
story 流优先、回退 related）。原因是 story 接口**没有分页游标**（只拉一次当种子），无限刷必须靠推荐流的 idx 分页。

据此两个接口各得其所（与 BiliPai 完全对齐）：
- **顶栏「刷视频」入口**：推荐流 `fetchFeed(idx)` 分页补货（无限刷）；
- **story 接口**：作为 story 会话的种子流（从入口视频锚定的竖屏短视频流，带完整封面/标题/UP）。

## 二、功能与链路

**入口**：首页顶栏原「单/双列切换」按钮 → **「刷视频模式」按钮**（PlayArrow 图标）。单/双列布局
本身不受影响：`singleColumn` 状态与 HomeVideoPage 的网格逻辑保留，切换入口由设置页
（FeedSettingsScreen 的 homeFeedSingleColumn）继续提供，无功能损失。

**打开链路（OPPO 无缝，文档 13772 同一套契约）**：
1. 点击 → 取推荐流第一条视频卡（target + cover，零额外请求）；
2. `LocalStoryCardOpener`（story 专用 `SeamlessCardOpener` 实例）→ `tryOpen(anchor = 按钮上的
   SeamlessAnchor 零绘制 View, decorateAnchor = false, fallbackColor = 按钮底色)` →
   `setSeamlessView` + `startActivity(intent, bundle)`；
3. 系统 morph：**按钮位置的圆角色块 → 全屏刷视频页**（B 站官方入口同款语言；decorated 封面在
   48dp 锚点上比例失真不可读，故用纯色 morph）；
4. 无缝不可用/注册失败 → 回退 `onEnterStoryMode(target)` 普通打开（上一轮统一的 fade+scale
   窗口动画）；不支持无缝的设备再降级为普通详情打开（用户可手动下滑进全屏刷）。

**页面**：VideoDetailActivity（story extra）→ `VideoScreen(storyMode = true)` → 常驻全屏的
`PortraitSwipePager`（页 0 = 入口视频，队列 = story 流 + 推荐流分页接力 + detail.relates）。
无紧凑态：返回键/「全屏」钮 = 关闭页面（finish，系统成对返回动画）。
