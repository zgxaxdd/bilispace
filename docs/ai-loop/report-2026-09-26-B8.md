## 2. 两处**刻意不收口**（本批真正值得记下来的判断）

`CommentRepository.kt:176` 与 `LiveRoomMessageRepository.kt:194` 长得一模一样：

```kotlin
runCatching { publishedRecordRepo.save(...) }.onFailure { Logger.e(...) }
```

按 ST-06 的清单顺手全改是**错的**：走到这一行时**评论/弹幕已经发送成功**了，
换成 `runCatchingCancellable` 会把取消传播回发送路径，`sendReply` 从此抛 CE，
上层把一次**已经成功的发送**改判为失败 —— 表现是"发出去了但输入框不清空/列表不刷新"，
比原来的"日志误报 + 本地记录丢一条"更伤用户。

正解是 ST-06b：把这条"提交后的本地记账"包进 `withContext(NonCancellable) { … }`
—— 既不把取消传播出去，也不让记账丢，同时不再把取消误报成失败。
这需要一个单独的设计确认（`save` 里是否有别的调用者依赖可取消语义），不在本批顺手做。

**并且把它变成机器检查**：两处各留一段带 `ST-06b` 标记的注释，
守卫断言"标记必须在、裸 runCatching 必须在"，谁想顺手一起改就得先把 ST-06b 做掉。
注释被 `codeOf()` 清掉这件事本身也让我踩了一次：标记查的是**未清空的原文**，
代码形态查的才是清空后的。

## 4. 踩到的一条语言坑（编译器接住了）

KDoc 里写 `feature/*` 会让整个文件语法错误 —— **Kotlin 的块注释是可嵌套的**，
那个 `/*` 开了一层新注释，`*/` 只关掉了内层。报 `Syntax error: Unclosed comment`。
（对比：Java 不会。这条靠编译发现，没逃过门禁。）
