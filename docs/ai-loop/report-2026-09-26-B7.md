## 1. 先把 B6 的建议证伪了一半

B6 报告里我写的修法①是"CI 的守卫步骤加 `--rerun-tasks`"。**这一批先查 CI 现状，发现两处需要修正**：

1. `pr.yml:26` 用的是 `gradle/actions/setup-gradle@v5` —— 它会**开启构建缓存**。
   所以"守卫可能被跳过"在 CI 里是真实存在的（`FROM-CACHE` 直接不执行任务），
   不只是本地问题；但触发面比 B6 写的窄：**只有改动不进字节码时才会命中**
   （改注释、把文件挪到拼错的同包名目录等 —— 恰好是这些守卫最该拦的那类）。
2. `--rerun-tasks` 是**整条任务图**全部重跑（含编译），代价太大。
   Gradle 有单任务粒度的 `--rerun`，只需要测试步骤真跑，编译照样增量。

`build.yml` 复核后**不跑单测**（只有 `assembleRelease`），所以不需要动。

## 2. 改动

`.github/workflows/pr.yml` 的 Unit tests 步骤加 `--rerun`，并把原因写成注释
（为什么不能省这几十秒：Test 任务的声明输入只有 `testClassesDirs`/`classpath`，
而结构守卫是运行时自己 `File().readLines()` 扫源码的，被扫文件不在输入里）。

## 4. 本地侧的配套口径（不改进程，只登记做法）

本地验证要"守卫确实跑过"时，二选一：
```powershell
.\gradlew.bat :app:testDebugUnitTest --rerun          # 单个模块
find . -type d -path "*/build/test-results/testDebugUnitTest" -exec rm -rf {} +   # 全部（删输出即失效）
```
B6 那次全量验证就是用第二种做的。**看日志时要确认测试任务是 `> Task :x:testDebugUnitTest`
而不是带 `UP-TO-DATE` / `FROM-CACHE` 后缀** —— 否则"全绿"只代表缓存里曾经绿过。
