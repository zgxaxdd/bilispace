## 一、任务背景与目标

### 1.1 现状

应用里的「刷视频模式」＝竖屏全屏上下滑切换视频（BiliPai 的 Story/竖屏连播同款）。
当前**只有竖屏视频能进入**：`VideoScreen.kt` 的启用判据里带了 `isPortraitVideo`
（横屏视频直接不启用，停留在"单视频全屏"），因此横屏视频缺少该入口。

### 1.2 目标

让**横屏视频也能进入刷视频模式**，且：

1. **保持之前的全部操作逻辑不变**——不新增任何控件/按钮/图标/菜单项；
2. 进入方式改为：**在视频简介区域下滑**进入刷视频模式；
3. **原有全屏播放功能保持不变**（全屏/还原按钮行为不变、独立）。

## 三、方案设计细节

### 3.1 核心思路

**把"进入刷视频模式"从"全屏的副产品"改成"简介区下滑手势的显式动作"**：

- 之前：进全屏 → `LaunchedEffect(fullOn, detail)` 里按 `isPortraitVideo` 决定是否开会话
  （竖屏才进）。横屏因此进不去。
- 现在：**手势驱动**——简介区下滑 → 置一个 `swipeModeRequested` 标志 → 进全屏 +
  开会话，**不再看画幅**。这样横屏视频也能进，且**没有新增任何控件**（满足 R1/R2）。

### 3.2 「简介区域下滑」的判定

- 简介区域 = 详情页视频标题下方那块可滚动/可展开的文字区（标题 + UP + 播放量/弹幕/评论数
  + 简介正文 + 标签 + 合集/推荐列表所在的详情内容区）。
- 交互语义：手指在**该区域**起手并**向下滑**（dy 超过阈值、且横向位移不足以判定为横向滚动）
  → 进入刷视频模式。
- 与既有手势的边界（重要，别互相抢）：
  - 该区域本身的**纵向滚动**（简介很长时）优先；下滑到**顶部还继续下拉**才触发进入
    （即"边缘下滑"，和下拉刷新同源的判据，避免用户只是想滚动简介就进了连播）；
  - **播放器区域**的既有手势（单击显隐控件、双击点赞/暂停、左右滑 seek、上下滑亮度/音量、
    捏合缩放）**一律不动**；
  - **列表区域**（合集/推荐）的上下滚动**不动**，不起手触发。

### 3.3 进入后的行为（横屏）

- 会话内仍**锁竖屏**（既有设计）：横屏视频在竖屏全屏里以 letterbox 呈现——这正是
  "以竖屏全屏方式显示播放内容"的预期形态；
- 需要真正满屏时，会话内顶栏仍有手动「横屏」胶囊（既有能力，不动）；
- 队列/锚点/预取/加载层/评论/互动栏全部沿用既有实现（见 §4.3），不重写。

### 3.4 与"全屏"的关系（R3）

| 操作 | 行为 |
|---|---|
| 「全屏」按钮 | 只进全屏，**不开**刷视频会话（若产品上希望全屏也进会话，保留原判据即可，但**不要**让手势入口依赖它） |
| 「还原」按钮 | 按原逻辑返回（详情路径形变回缩；story 路径退出会话露出详情页——该逻辑本会话已接好，勿回退） |
| 简介区下滑 | 进全屏 + 开刷视频会话（**本任务新增的唯一触发**） |

## 五、验收标准

### 5.1 功能验收（真机，OPPO PLC110 / Android 16）

| # | 步骤 | 期望 |
