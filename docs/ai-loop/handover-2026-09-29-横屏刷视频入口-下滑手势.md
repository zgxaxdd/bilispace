## 一、任务背景与目标

### 1.1 现状

「刷视频模式」＝竖屏全屏上下滑切换视频（BiliPai 的 Story/竖屏连播同款）。
当前**只有竖屏视频能进入**：`VideoScreen.kt` 的会话启用判据里带 `isPortraitVideo`，
横屏视频因此停留在"单视频全屏"，没有该模式入口。

### 1.2 目标

横屏视频也能进入刷视频模式，且严格满足：

1. **保持之前的全部操作逻辑不变，不新增任何控件/按钮/图标/菜单项**；
2. 进入方式改为：**在视频简介区域下滑**；
3. **原有全屏播放功能保持不变**。

## 三、方案设计细节

### 3.1 核心思路

把"进入刷视频模式"从**"全屏的副产品"**改成**"简介区下滑的显式动作"**：

- 旧：进全屏 → `LaunchedEffect(fullOn, detail)` 按 `isPortraitVideo` 决定是否开会话
  （竖屏才进）→ 横屏进不去；
- 新：**手势驱动** —— 简介区下滑 → 置 `swipeModeRequested` → 进全屏 + 开会话，
  **不再看画幅**。横屏因此能进，且**零新增控件**（R1/R2 同时满足）。

### 3.2 「简介区域下滑」的判定（最关键，易翻车）

- 简介区域 = 详情页视频标题下方那块内容（标题 + UP + 播放量/弹幕/评论数 + 简介正文 +
  标签 + 合集/推荐列表所在的详情内容区）。
- 交互语义：手指在**该区域**起手并**向下滑**（dy 超阈值、横向位移不足以判为横向滚动）
  → 进入刷视频模式。
- 与既有手势的边界：
  - 该区域自身的**纵向滚动优先**；**下滑到顶还继续下拉**才触发（"边缘下滑"，与下拉刷新
    同源判据）——否则用户只是想滚简介就误进连播；
  - **播放器区域**既有手势一律不动（单击显隐控件、双击点赞/暂停、左右滑 seek、
    上下滑亮度/音量、捏合缩放）；
  - **列表区域**（合集/推荐）的上下滚动不起手触发。

### 3.3 进入后的行为（横屏）

- 会话内仍**锁竖屏**（既有设计）→ 横屏视频在竖屏全屏里 letterbox 呈现，
  即"以竖屏全屏方式显示播放内容"；
- 要真正满屏时，会话内顶栏仍有手动「横屏」胶囊（既有能力，不动）；
- 队列/锚点/预取/加载层/评论/互动栏全部沿用既有实现（§4.3），不重写。

### 3.4 与「全屏」的关系（R3）

| 操作 | 行为 |
|---|---|
| 「全屏」按钮 | 只进全屏，**不开**连播会话 |
| 「还原」按钮 | 按原逻辑返回（详情路径形变回缩；story 路径退出会话露出详情页） |
| 简介区下滑 | 进全屏 + 开连播会话（**本任务新增的唯一触发**） |
