## 复核

`feature/bbspace/.../BbSpaceScreen.kt` 的导入入口：

```kotlin
val result = withContext(Dispatchers.IO) {
    runCatching { …contentResolver.openInputStream(uri)… ; publishedRecordVm.importJson(json) }
}
result.onSuccess { Toast "已导入 $count 条记录" }.onFailure { Toast "导入失败" }
```

`scope` 是 `rememberCoroutineScope()`，离开这个界面就取消 → 读文件/写库中途抛
`CancellationException` 被裸 `runCatching` 吞下 → 用户看到「导入失败」，
而实际是他自己关掉了页面。**与 ST-06b 的区别**（B8 立的判据）：这里操作本身没完成，
不存在"把成功的操作改判为失败"的反向伤害，所以传播取消是对的，不需要 `withContext(NonCancellable)`。

依赖方向未动：`feature/bbspace` 原先就声明了 `:core:common`（B8 那批加的）。
