### 1.2 关键证据一：NavHost 换掉了返回键的接法

同一份反编译对比（`navigation-compose`）：

| 版本 | `NavHostKt` 里的返回键接线 |
|---|---|
| **2.5.1** | 引用 `OnBackPressedDispatcher`、`setOnBackPressedDispatcher`、`enableOnBackPressed`；内部类 `NavHostKt$NavHost$3` 调 `enableOnBackPressed(true)`，dispose 时置回 |
| **2.10.1** | 这三个符号 **0 命中**。改成 `NavHostEventHandler : androidx.navigationevent.NavigationEventHandler<NavBackStackEntryInfo>`，经 `rememberNavHostEventHandler(navigator, backEnabled)` 注册 |

2.10.1 的 `NavHostKt`（字节码）：
```
1038: ComposeNavigator.getBackStack() → collectAsState
1058: List.size() ; 1064: if_icmple 1071     // size <= 1 → false
1067: iconst_1                                // size > 1  → true
1075: rememberNavHostEventHandler(composeNavigator, <这个布尔>)
```
`rememberNavHostEventHandler`（`NavHostEventHandlerKt`）：
```
23: LocalNavigationEventDispatcherOwner.getCurrent()   // 缺了就 throw ISE
59: owner.getNavigationEventDispatcher()
    LifecycleStartEffect(enabled, handler) {
        handler.setBackEnabled(enabled)
        onStopOrDispose { handler.setBackEnabled(false) }   // ← 关键：会被复位
    }
    DisposableEffect(dispatcher, handler) { dispatcher.addHandler(handler, PRIORITY_DEFAULT) ... }
```
`NavHostEventHandler.onBackCompleted()` → `prepareTransition()`（`backStack.size < 2` 直接 return）
→ `navigator.popBackStack(entry, saveState = false)`。

### 1.3 关键证据二：旧链路在 Compose 下已经是**死链**

`NavController`（2.10.1）里仍有：
```
public void enableOnBackPressed(boolean)
public void setOnBackPressedDispatcher(OnBackPressedDispatcher)   // 内部 addCallback(...)
private void updateOnBackPressedCallbackEnabled()
      → onBackPressedCallback.setEnabled(enableOnBackPressedCallback && getDestinationCountOnBackStack() > 1)
```
但 **`navigation-compose` / `navigation-runtime` / `navigation-common` 全族里没有任何一处调用
`setOnBackPressedDispatcher` 或 `enableOnBackPressed`**（逐类反编译 + 字节串搜索，0 命中）。
也就是说：`NavController.onBackPressedCallback` 在 Compose 路径下**永远不会被挂到 dispatcher 上**。

### 1.4 关键证据三：activity 1.13.0 把两套管线合并了，并决定"是否注册系统回调"

`ComponentActivity`：
```kotlin
public void onBackPressed() {
    getOnBackPressedInput().backCompleted();      // → navigationevent 管线
}
public NavigationEventDispatcher getNavigationEventDispatcher() {
    return getOnBackPressedDispatcher().getEventDispatcher$activity();   // ← 就是同一个 dispatcher
}
```
`OnBackPressedDispatcher.addCallback(cb)`：
```
new OnBackPressedCallbackInfo(cb, lifecycleOwner, ...)
cb.createNavigationEventHandler$activity(info)
getEventDispatcher$activity().addHandler(handler, ...)      // 也进同一个 navigationevent dispatcher
```
→ 所以 `BackHandler`（activity-compose）与 NavHost 的 `NavHostEventHandler` **在同一个
dispatcher、同一套优先级体系**里竞争 —— 这一点决定了修复该写在哪（见 1.6）。

`OnBackInvokedInput.updateBackInvokedCallbackState(hasEnabledHandlers)`：
```
hasEnabledHandlers == false → onBackInvokedDispatcher.unregisterOnBackInvokedCallback(cb)
hasEnabledHandlers == true  → registerOnBackInvokedCallback(priority, cb)
```
**这就是"整个 App 被退掉"的总开关。** 没有任何 enabled handler 时：
```
平台默认 back → ComponentActivity.onBackPressed() → backCompleted()
  → dispatcher.dispatchOnCompleted() → 没有 enabled handler
  → onBackCompletedFallback() = fallbackOnBackPressed.run()
  → androidx.core.app.ComponentActivity.onBackPressed() → Activity.onBackPressed()
  → finishAfterTransition()
```
（`OnBackPressedDispatcher` 的 fallback Runnable 反编译确认：`onBackPressedDispatcher_delegate$lambda$0$0`
里就是 `invokespecial androidx/core/app/ComponentActivity.onBackPressed:()V`，并吞掉
"Can not perform this action after onSaveInstanceState"。）

### 1.5 真机症状与证据的对应

| 用户所见 | 机制 |
|---|---|
| 「退出动画一直是那个**缩放**动画」 | 那是 `finishAfterTransition()` 的**系统任务关闭动画**（ColorOS 的"关闭=缩放"），不是应用内转场 |
| 「打开和退出**不是一个**」 | 打开走 NavHost 的 `enterTransition`（应用内 Compose），退出走系统窗口层 —— 结构上不可能对称 |
| 「不管怎么调过渡动画都**不生效**」 | `transition_style`/`animationSpeed` 只喂给 `NavHost` 的四个过渡参数；系统任务关闭动画不读它 |

真机实测（`adb shell input keyevent KEYCODE_BACK`，设置页已打开、日志有 `enter main -> settings`）：
按返回后**没有任何 pop 相关日志**，`dumpsys activity activities` 的 `ResumedActivity` 变成
`com.android.launcher/.Launcher` —— 即 MainActivity 被 finish ✅ 与上面的链路完全一致。

> ⚠️ 排查中踩过的一个坑（已写进守卫）：2.10.1 的过渡规格是**三档**
> （`inPredictiveBack` → 目的地级 → NavHost 级），系统返回命中第一档
> `predictivePopEnter/ExitTransition` —— **App 没传这两个参数时它既用不上设置的风格，
> 也不打我们那四条日志**。所以"没有 popExit 日志"本身不足以判定"没弹栈"，
> 权威判据是 `ResumedActivity`。

### 1.6 修复（已实现）

`app/src/main/java/com/naaammme/bbspace/navigation/AppNavHost.kt`，写在 `NavHost(` **之前**：

```kotlin
val rootBackStack by rootNavController.currentBackStack.collectAsStateWithLifecycle()
val canPopRoot by remember(rootBackStack) {
    derivedStateOf { rootBackStack.count { it.destination !is NavGraph } > 1 }
}
BackHandler(enabled = canPopRoot) { rootNavController.popBackStack() }

NavHost(
    ...,
    enterTransition = { transitions.enter(this) },
    exitTransition = { transitions.exit(this) },
    popEnterTransition = { transitions.popEnter(this) },
    popExitTransition = { transitions.popExit(this) },
    // 预测式返回也走同一套：不接这两个参数时 2.10.1 用内置默认值（风格不一致 + 日志不可见）
    predictivePopEnterTransition = { _ -> transitions.popEnter(this) },
    predictivePopExitTransition = { _ -> transitions.popExit(this) }
)
```

**为什么必须在 `NavHost` 之前**：`NavigationEventProcessor.addHandler` 用
`ArrayDeque.addFirst` 插入，`resolveEnabledHandler` 取"第一个 enabled"（javap 实证）
→ **后注册者优先级更高**。写在前面，优先级天然是：

1. 目的地内部的 `BackHandler`（评论面板/搜索/直播，后注册）——"先关面板再弹栈"不受影响；
2. NavHost 自己的 `NavHostEventHandler`（**带预测式返回跟手预览**）；
3. 本兜底处理器 —— 只在 2 失效时接管（生命周期竞态 / 进程恢复后
   `ComposeNavigator.backStack` 与 `NavController` 失步）。

写在后面会把兜底顶到最高优先级，抢掉预测式预览与面板语义（两个子代理都建议写在之后，
**经优先级实证后改回之前**）。

**判据为什么不能用 `backStack.size > 1`**：根图（`NavGraph`）本身也算一项，
停在首页时 `size == 2` 但无可弹目的地 —— 那样兜底会把返回键吃掉、用户退不出 App。
用 `count { it.destination !is NavGraph } > 1`，与 `NavController` 内部判据一致。

### 1.7 守卫测试（新增）

`app/src/test/java/com/naaammme/bbspace/navigation/NavBackHandlingGuardTest.kt`（5 条）：
1. 扫描器可达性（防假绿）；
2. 必须存在 `BackHandler(enabled = canPopRoot) { rootNavController.popBackStack() }`，
   且**不许**回退到 `enableOnBackPressed` / `setOnBackPressedDispatcher`（死链路）；
3. 判据必须是 `count { it.destination !is NavGraph } > 1`；
4. **位置**：兜底必须在 `NavHost(` 之前（优先级要求）；
5. NavHost 六个过渡参数必须接满（含 predictive 两个）。

### 1.8 还剩下的、**修不了**的部分（要跟用户讲清楚）

- **退出到桌面**的动画是系统任务关闭动画，应用只能通过 manifest 的
  `android:windowAnimationStyle` 影响 **Activity 之间**的转场
  （`app/src/main/res/values/themes.xml` 的 `WindowAnimation.Bbspace` 只定义了
  `activityOpen*/activityClose*` 四项，**没有** `taskOpen*/taskClose*`），
  系统"关闭应用"那一档不受控。
- 用户当前设置 `transition_style = NONE`：应用内四个方向本来就是"无动画"
  （这是设置项的值，不是 bug）。改成 `SHARED_AXIS_X`（默认）或 `FADE_THROUGH` 后，
  **打开/返回都会是同一套风格**（修好之后"返回"也走 NavHost 了）。

## 二、问题 1 的修复（加载动画 + 预览图）

### 2.1 加载动画"不出现"的真根因（纯代码级定位）

用括号配平分析 `VideoPlayerPane.kt` 的结构（工具输出）：

```
476 d=3  Box(                          ← 播放器容器，内容缩进/depth = 4
...
678 d=4  }                              ← ★ 这个括号关闭了 Box
680 d=3  if (activeDialog == Quality)   ← 之后的对话框都在 Box **外面**
...
730      SwipeWaitVeil(...)             ← 我的加载层也在 Box 外面 ✗✗
```
`CompositionLocalProvider` 的内容 lambda 允许发多个节点，于是加载层成了它的
**第二个子节点**，被父级布局排到屏幕之外：`remember`/`LaunchedEffect`/
`onGloballyPositioned` 全都正常（日志也说 `veil: visible=true mounted=true`），
**但永远画不出来**。真机验证：把背景临时改成纯红仍然不可见 → 确定是布局位置问题，
不是状态问题。

**修法**：把 `SwipeWaitVeil(...)` 移进播放器 Box，作为**最后一个子节点**
（在 678 行那个 `}` 之前）。修复后真机截图（`docs/ai-loop/shots/c8_veil_forced.png`
与框序列）确认：暗色渐变 + 外层扫光弧 + 内层反向细弧 + 双层轨道粒子（带拖尾）+
中心呼吸光核 ✅。

### 2.2 预览图取景

- 新增 `BiliCoverSize.PlayerPreview("@1080w_85q.webp")` 与
  `BiliImageVariant.PlayerPreview`：**只限宽 + 限质量、不裁切**（原有三档都带 `_1e_1c`，
  会按 16:9/4:3 裁掉主体）。
- `SwipeCoverPage` 改用 `PlayerPreview` + `ContentScale.Fit`：预览按封面**原始比例
  居中显示**，与随后播放的视频取景一致 → 封面 → 首帧不再有比例跳变。

### 2.3 加载层的行为约定（保持）

- 判据：`waitingFirstFrame = waitingKey != null`，`waitingKey` 由 `currentKey` 置位、
  由"真的出帧"或"这一支出错"清除（**粘滞**，避免 `hasRenderedFirstFrame` 在切流瞬间
  仍是上一支的 `true` 造成闪）。
- 位置：播放页 Box 最后一个子节点（盖住视频/弹幕/中央播放键/控制栏），
  自身不带 `pointerInput`，不挡上下滑。
- 另外：`VideoScreen` 的"单播放器"分支（story 入口在 `bootstrapStorySession` 返回前
  锚点还是 null）也接了同一个加载层，消除打开瞬间的黑屏。

## 四、挂账

1. `predictivePop*` 只接了"用同一套 pop 过渡"，更细的跟手曲线（swipeEdge 方向感）没有单独设计；
2. 任务级窗口动画（退出到桌面）无法应用内控制；若要做到"退出也同族"，只能靠
   `finishAfterTransition` 的系统行为，属于平台能力边界；
3. 建议在设置页的「过渡动画」说明里补一句："退出到桌面的动画由系统提供，不受此项控制"。
