## 二、4.1 根因链（含真机证据）

### 2.1 修复前的真机复现

深链打开 9:16 视频 → 播放带下方下滑进全屏 → 上滑一次：

- 截图 `docs/ai-loop/shots/c7_03_after_swipeup.png`：**2800x1272（已转横屏）**，画面是
  `SwipeCoverPage`（封面铺满 + 底部「标题 / @UP」渐变条）——即"能滑动但不播放下一个"；
- logcat：`PortraitSwipe: activate: portrait=true queue=11 active=true` 之后**再无任何
  页切换/播放日志**（当时 pager 里没有诊断点），但 `PlayViewUnite` 显示新视频的流**已取到**。

### 2.2 根因（代码级）

`PortraitSwipePager` 用字符串判"这一页是不是播放器页"：

```kotlin
// 修复前
if (entry.key == currentKey) { VideoPlayerPane(...) } else { SwipeCoverPage(...) }
```

两侧 key 是**在不同时刻**算出来的：

| 时刻 | 来源 | relate 卡（无 bvid） |
|---|---|---|
| 建队时 | `SwipeEntry.key = bvid.ifEmpty { "aid:${target.aid}" }` | `aid:117339261503379` |
| 取流完成后 | `currentKey = videoState.ids.bvid.orEmpty().ifEmpty { "aid:${ids.aid}" }`，而 `ids` 被 `applyDetailResult` 整体换成服务端解析结果（bvid 已补齐） | `BV1Kyas6wEuz` |

→ 同一页在**取流完成的那一瞬间**由命中变失配，播放器页落空；锚点页（页 0，bvid 本来就全）
不受影响，所以症状是"只有后续页不播"。取流前 pager 已经命中过一次，所以用户看到的是
"先黑/封面 → 永远封面"，而不是"从未起播"。

### 2.3 修法（三处，互不依赖）

| 位置 | 改动 |
|---|---|
| `swipe/PortraitSwipeQueue.kt` | 新增 `SwipeEntry.isCurrentVideo(bvid, aid)`：**aid 优先、bvid 兜底**（两侧都有 aid 时以 aid 为准——对"bvid 后来才补齐"天然免疫）；新增与 `SwipeEntry.key` 同构的 `swipeKey(bvid, aid)` |
| `player/PortraitSwipePager.kt` | 参数由 `currentKey: String` 换成 `currentBvid: String?` + `currentAid: Long`（**不让调用方先拼字符串**，否则"取流前的 key"与"取流后的 key"又混成一个）；渲染门与迟到对齐都改用 `isCurrentVideo`；`requestedKey` 只保留"同一目标别重复发请求"的去重语义 |
| `VideoViewModel.openSwipeTarget` | 同条目短路一并改成 aid 优先（否则"aid-only 目标 vs 已补齐 bvid 的栈顶"会被判成不同目标，白白重开一次播放） |
| `core/video/VideoDetailRepository.mapRelates` | `bvid = bvid(uri) ?: avToBv(aid)`（治本：relate 卡本身补齐，详情页的相关列表也受益） |
| `swipe/PortraitSwipeQueue.kt` 三个映射 | `withBvid()` 兜底补全（relate / story / 首页推荐流三个数据源都不会再产出 aid-only 条目） |

### 2.5 avToBv 的真值校验（路线 A 的正确性）

| aid | 本机 `avToBv` | B 站 live API `x/web-interface/view` | 结论 |
|---|---|---|---|
| 2 | `BV1xx411c7mD` | `BV1xx411c7mD` | ✅ |
| 170001 | `BV17x411w7KC` | `BV17x411w7KC` | ✅ |
| 117339261503379（新版长 aid） | `BV1Kyas6wEuz` | `BV1Kyas6wEuz` | ✅（旧算法在此错成 `BV1d54t1F77p`） |
| 真机旁证 | `avToBv(117257657124396)=BV1XmYX6dEfD` | 取流后服务端解析出 `current=BV1XmYX6dEfD` | ✅ 现场一致 |

> 注意：BiliPai 自己的单测里 `av2bv(2) == "BV1xx411c7m9"` 与其实现、与 live API 都**不一致**
> （真实值是 `BV1xx411c7mD`）。bbspace 侧以 live API 真值为准，**没有照抄那行断言**。

### 2.6 为什么不需要交接书路线 B（移植独立 relate 接口）

路线 B（`GET x/web-interface/archive/related`）解决的问题是"relate 卡的 bvid 缺失"。
本轮的 `avToBv` 补齐在同一份 gRPC 响应上已经拿到**真值**（2.5 表），且真机验证一致；
再引一个接口会多一份网络往返、一份模型、一份失败分支，收益为零。**不采纳**（记为挂账，
若将来出现 avToBv 覆盖不到的 id 形态再评估）。

### 2.7 为什么也没走路线 C

`StreamPlaybackSession` 对 aid-only 目标本来就是好的（2.1 的日志），无需改动——
**播放链路一行没动**，改动全部落在"页身份"和"数据补齐"两处。

## 三、4.2 根因链（旋转动画）

### 3.1 修复前的代码

```kotlin
DisposableEffect(act, fullOn, settingsState.playback.autoRotateFullscreen, isPortraitVideo) {
    act?.requestedOrientation = if (fullOn && autoRotateFullscreen && !isPortraitVideo) {
        ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE
    } else {
        ActivityInfo.SCREEN_ORIENTATION_UNSPECIFIED
    }
    …
}
```

`isPortraitVideo` 的 remember key 是 `videoState.currentStream`：**切换视频的那一刻它是 null**
（新会话 `isPreparing`、取流未回）→ `false` → 写 `SENSOR_LANDSCAPE`（转屏动画）；
新流回来（竖屏）→ 写回 `UNSPECIFIED` → 再转回来。真机日志实证：

```
19:45:26.539  ViewRootImplExtImpl: … rotation=1 … bounds=Rect(0, 0 - 2800, 1272)   ← 已转横屏
19:45:27.118  PlayViewUnite: Stream … W: 674, H: 480                               ← 新流这时才到
```

### 3.2 修法

刷视频会话期间（详情全屏的上下滑 **或** story 常驻全屏）**锁竖屏**：

```kotlin
val portraitSwipeActive = swipeSessionActive || effectiveStoryMode
DisposableEffect(act, fullOn, autoRotateFullscreen, isPortraitVideo, portraitSwipeActive) {
    act?.requestedOrientation = when {
        portraitSwipeActive -> ActivityInfo.SCREEN_ORIENTATION_PORTRAIT
        fullOn && autoRotateFullscreen && !isPortraitVideo ->
            ActivityInfo.SCREEN_ORIENTATION_SENSOR_LANDSCAPE
        else -> ActivityInfo.SCREEN_ORIENTATION_UNSPECIFIED
    }
    onDispose { act?.requestedOrientation = ActivityInfo.SCREEN_ORIENTATION_UNSPECIFIED }
}
```

- 会话期间取 `PORTRAIT` 而不是 `UNSPECIFIED`：用户此刻要的是"连播"，方向由 pager 说了算，
  不听传感器（抖音/B 站官方竖屏连播同款）；会话结束/离开组合复位 `UNSPECIFIED`（沿用原有兜底）；
- 未进会话的"单视频全屏"路径**行为不变**（横屏视频 + 开关打开仍会转横屏，这是既有功能）。

**与 BiliPai 的差异（有意为之）**：BiliPai 在竖屏连播态是 **完全不写** `requestedOrientation`
（`VideoDetailPlatformPolicy.resolvePhoneVideoRequestedOrientation` 里 `if (isPortraitFullscreen) return null`，
调用方 `?: return@LaunchedEffect`），并关掉传感器方向监听 `shouldObservePhoneAutoRotate`。
两者都能消除"瞬时空流导致的翻转"；bbspace 选锁竖屏，额外挡住"用户手动转手机"。

### 3.3 真机验证

- 全部 11 张本轮截图均为 **1272x2800**（含 3 次横屏视频、1 次 story 模式、左右边缘滑动）；
- 修复前同一条路径的截图是 2800x1272（`c7_03_after_swipeup.png`）。

## 四、BiliPai 调研结论（本次新增，含"值得/不值得移植"）

调研对象：`_ref/BiliPai`（只读）。核心事实与 bbspace 的取舍：

### 4.1 已移植（本轮）

| BiliPai 机制 | 出处 | bbspace 落地 |
|---|---|---|
| `IdUtils.av2bv/bv2av` 本地换算 | `core/util/IdUtils.kt:26/49` | `VideoTargetTool.avToBv/bvToAv` + 5 条 live-API 真值单测 |
| 页身份与"当前播放"分离、身份**不随取流改变** | `PortraitVideoLoadPolicy.resolvePortraitPagePlaybackIdentity`（只认 bvid，为空即 null）；`currentPlayingBvid` 在**发请求的同一帧**写入（`PortraitVideoPager.kt:1029`） | `isCurrentVideo`（aid 优先/bvid 兜底）+ pager 收 `currentBvid/currentAid` 而不是拼好的字符串 |
| 竖屏连播期间不因传感器/视频比例改方向 | `VideoDetailPlatformPolicy.kt:640-643`、`:978-979` | 会话期间锁竖屏（3.2） |

### 4.2 值得移植、但不在本轮范围（挂账）

| 机制 | BiliPai 出处 | 说明 |
|---|---|---|
| playurl 预取（拖动偏移 0.25 预取相邻页 + 停稳后 1–3 条） | `PortraitVideoLoadPolicy.kt:34, 368-400` | bbspace 全仓无播放地址预取，每页都要等完整"详情 + 取流"往返；这是**起播手感**的最大缺口 |
| 字节级 head range 预热（视频 1.5MB / 音频 256KB 写 SimpleCache） | `PortraitVideoLoadPolicy.kt:35-36, 411-437` | 需要给 media3 DataSource 接 SimpleCache，独立立项 |
| 补货"凑满 8 条已验证"重试循环（最多 3 页） | `PortraitVideoPager.kt:1341-1412` | bbspace 的 `loadMoreSwipeQueue` 只拉一页，遇到空页/全被去重就"刷到头" |
| 竖屏过滤（只刷竖屏） | `PortraitPagerSwitchPolicy.kt:332-359` | BiliPai 逐条打 view 接口（并发 8）成本高；bbspace 应换轻量判据（story 流自带尺寸时） |
| 播完行为可配置（STOP / REPEAT / CONTINUE） | `PortraitVideoPager.kt:900-916` | bbspace 用播放器 repeat 设置代替：`player_repeat_mode=One` 时 `STATE_ENDED` 不发，自动翻页天然不触发 |

### 4.3 明确不移植

- `ViewInfo` / `RelatedVideo` 双型混排（`pageItems: SnapshotStateList<Any>`，4087 行巨型 composable 的根源）；
- 评论 / 弹幕 / 合集 / 画质 / 字幕全部内联进 pager（bbspace 走 `openVideo` 详情管线，已复用）；
- 竖屏直达 morph、letterbox 环境光采样、pager 内手势缩放（与本次两个 bug 无关；bbspace 已有等价物或收益/成本比低）。
