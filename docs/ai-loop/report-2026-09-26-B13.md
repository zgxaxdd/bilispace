**分区**：A-稳定 P1｜**级别**：A 级·可机器判定（接线）+ 需真机确认手感（转 L4-16）

## 复核修正（BACKLOG 低估了范围）

BACKLOG 只写了"缓存页 `release()` 无条件释放"。实际读源码核过之后：

1. **缺陷是双向的**。流会话侧的 `finishVideoPlayback`（`:532`）与 `finishLivePlayback`（`:876`）
   同样无条件 `playerEngine.release()` / `stopForReuse()`。所以不只"关缓存页会拆掉直播的播放器"，
   反过来"直播/详情页收尾"也会拆掉正在播的缓存视频。
2. **`stopForReuse` 和 `release` 一样是所有权动作**。它 `player.stop() + clearMediaItems()`，
   非占用者调用同样把别人的在播会话打断 —— 只守 `release` 会留一半洞。
3. **写媒体的点不是 1 处而是 4 处**：流会话 3 处（直播起播、VOD 起播、清晰度/音轨切换
   `applyVideoSelection`）+ 缓存 1 处。归属只能建立在"每次写之前声明归属"上，
   漏一处就会出现"实际是我写的、仲裁器却认为引擎归别人"。

## 设计

新增 `core/playback/.../PlayerEngineArbiter.kt`（`@Singleton`，无 Android 依赖）：

- `claim(holder)` —— 写引擎**之前**调用；抢占式，谁最后写谁负责收尾。
- `isHolder(holder)` —— 决定是否允许 `stopForReuse`（保留占用）。
- `release(holder): Boolean` —— `compareAndSet`，只有占用者能交还；返回 true 才允许 `playerEngine.release()`。

**为什么抢占而不是引用计数**：本仓只有一台播放器（`PlayerEngine` 是 `@Singleton`，
`Media3PlayerEngine` 内部就一个 `exoPlayer` 字段），两个会话不可能同时拥有媒体 ——
后写的 `setSource` 已经物理上覆盖了前者的媒体。引用计数会假装两者并存，
反而把"被抢走"这件事藏起来。

**为什么 claim 放在 setSource 之前**：若放在成功后，`setSource` 抛异常时没人是 holder，
随后那一侧的 release 会被仲裁挡掉，引擎里的半成品媒体再也清不掉。

**并发**：`setSource` 是挂起函数，恢复线程不保证是主线程（`applyVideoSelection` 就在
`runtimeScope.launch` 里），所以状态用 `AtomicReference`；`concurrentReleaseHappensExactlyOnce`
用 8 线程验证只有一次真正释放。

## 接线

| 位置 | 改动 |
|---|---|
| `DownloadPlaybackControllerImpl.open()` | setSource 前 `claim(DOWNLOAD)` |
| `DownloadPlaybackControllerImpl.release()` | `if (arbiter.release(DOWNLOAD)) playerEngine.release()` |
| `StreamPlaybackSessionImpl` 三处 setSource | 各自前面 `claim(STREAM)` |
| `finishVideoPlayback` / `finishLivePlayback` | release 走 `arbiter.release(STREAM)`；stopForReuse 走 `arbiter.isHolder(STREAM)` |

## 诚实边界

- 语义与接线都离线证明了，但**"小窗/后台播放连续性变好没有、有没有引入新的中断"只能真机判定**
  → 转 **L4-16**（含三条对照：缓存播放中收直播页、直播中开缓存页、小窗里播放时关缓存页）。
- 本批**没有**给 `play/pause/seekTo/setSpeed` 加归属检查：它们只作用于"当前媒体"，
  非占用者调用影响的是别人的会话，但这类调用在 UI 上只可能来自正在展示的那一页，
  加闸门会把"缓存页控制自己刚写的媒体"也挡掉，属于超出缺陷范围的行为变更。已作为观察项写进报告，
  不做。
- `Media3PlayerEngine` 内部的错误自愈重建播放器（`recover`）不经仲裁器：那是引擎自己的
  实例生命周期，不涉及会话归属，刻意不动。
