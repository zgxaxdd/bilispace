# 批次报告 · C4 · 2026-09-28 · 竖屏全屏「上下滑刷视频」移植（BiliPai PortraitVideoPager → bbspace）

**分区**：A-功能 P1｜承接 `report-2026-09-28-C3.md`。用户原话：「调研 bilipai 为什么可以在竖屏模式视频全屏后，可以像刷抖音一样无限的刷视频，请全面的将这个功能移植过来，做好适配和优化工作」。

## 一、BiliPai 调研结论（为什么能无限刷）

BiliPai 的实现核心在 `app/src/main/java/com/android/purebilibili/feature/video/ui/pager/`
（PortraitVideoPager.kt 4087 行 + 12 个 Policy 文件，另两个入口：StoryScreen 独立故事流、
VideoDetailPortraitOverlayAdapter 详情页竖屏 overlay）。四个支柱：

1. **无限 = 页数动态增长的 VerticalPager**：`rememberPagerState { pageItems.size }`，
   `pageItems: mutableStateListOf<Any>`（ViewInfo/RelatedVideo 混排）**只追加、永不重建**
   （注释原话："seed once, then only append"），滑到尾部触发加载更多把页数撑大。
2. **数据接力三层**：初始 = 详情页相关推荐（或 Story 短视频流优先）；耗尽前拉首页推荐流
   （`getHomeVideos(idx)` 分页，倒数第 1/4 页触发、最多 3 次尝试凑够 8 条）；登录时并入稍后再看。
   配套去重三件套：bvid 硬去重 + 标题签名相似去重（规范化标题/封面 key/中文分词关键词交集/
   时长差）+ UP 主多样性（最近 12 条同 UP ≤ 2）；确定性洗牌种子防重复进入同列表；
   可选「只留竖屏视频」过滤（并发 8 查详情尺寸）。
3. **单播放器复用 + 三段式切换**：优先复用详情页 `sharedPlayer`（ExoPlayer），每页一个
   `AndroidView(PlayerView)`，仅当前页且播放器正在播该 bvid 时 rebind surface，其余页渲染封面；
   切换三段式 = ①拖动偏移跨 ±0.25 预取 playurl + 头部字节（视频 1.5MB/音频 256KB）写磁盘缓存；
   ②currentPage 跨过 snap 中点（不必等手势结束）立即取流切 `MergingMediaSource`，
   generation 计数防迟到结果串台；③停稳提交评论/上报。
4. **手势隔离**：双指缩放（scale>1.01）、评论面板打开、评论进度>0 时禁用 pager 滑动；
   播完自动进下一页（行为可配置）；竖屏流进度回 Drawer 状态按 ≥1s 位置增量提交（防重组风暴）。

## 二、移植方案（bbspace 化，关键差异与取舍）

BiliPai 的全屏是**独立页面 + 自带播放器管理**；bbspace 的全屏是 `VideoScreen` 的 `fullOn`
状态，取流/弹幕/历史/清晰度全部走 `VideoPlaybackController.openVideo` 既有管线。因此移植时
**只搬数据层与 pager 结构，播放管理整体复用**——`VideoRelate.target` 本就是 `VideoTarget.Ugc`，
`detail.relates` 每切一个视频自带新一批推荐，天然构成接力流（无需 BiliPai 的首页推荐流补货层）。

### 落地文件

| 文件 | 内容 |
|---|---|
| `feature/video/.../swipe/PortraitSwipeQueue.kt`（新） | 纯数据层：`SwipeEntry`、`swipeEntryFromDetail`（页 0 锚点）、`swipeEntriesFromRelates`、`appendSwipeEntries`（bvid + 规范化标题 + 封面 key 三档去重、UP 主多样性最近 12 条 ≤2）、`shouldExtendSwipeQueue`。与 BiliPai 的取舍：标题签名压缩为「去括号段/标点 + 封面 key」两档（接力流同 UP 互推重复率高，三档硬去重已覆盖实测场景），多样性按作者名（VideoRelate 无 mid） |
| `feature/video/.../swipe/PortraitSwipeQueueTest.kt`（新） | 9 个纯函数单测（去重/多样性/顺序保持/映射丢弃/补流判据） |
| `feature/video/.../VideoViewModel.kt` | `swipeAnchor`/`swipeQueue` StateFlow；`beginSwipeSession()`（进入全屏时锚定当前视频 + 种子队列）；`openSwipeTarget(entry)`——**替换栈顶**而非 `openTarget` 的压栈（刷视频是同一浏览会话，返回键应退出详情而不是逐个回放刷过的视频，B 站官方/BiliPai 同语义）；init 监听 `videoState.detail` 变化自动接力 merge（幂等） |
| `feature/video/.../player/PortraitSwipePager.kt`（新） | `VerticalPager`（页数 = 锚点 + 队列，动态增长 = 无限）；**播放器唯一**：仅 `entry.bvid == currentBvid` 页组合 `VideoPlayerPane`（PlayerView 经 PlayerViewTargetBinder 绑进程级播放器），其余页 `SwipeCoverPage`（封面 Crop + 底部标题/UP 渐变条 + 取流中 loading）；翻页监听 `snapshotFlow { currentPage }` **跨过 snap 中点即发切换**（BiliPai 提前起播同款） |
| `feature/video/.../VideoScreen.kt` | fullOn 分支分叉：进入全屏瞬间 `beginSwipeSession()` + `swipeSessionActive`（取**进入时**的 isPortraitVideo，会话内恒定——中途刷到横屏视频不能让 pager 消失打断滑动，页面 FIT 自适应）；队列空（无可刷推荐）回退单视频全屏现状 |
| `VideoLogicGuardTest`（改） | 新增 `portraitSwipePagerStaysSinglePlayerAndStackTopReplace`：VerticalPager ×1、pager 内 VideoPlayerPane ×1（播放器唯一）、requestedBvid 防震荡、swipeSessionActive 启用判据、openSwipeTarget 必须 dropLast(1)+target（不许回退压栈） |

### 关键设计点

- **播放器页跳转零黑帧**：翻页时旧页仍持有播放器（用户看着它滑走），新页先显示封面；新流到达
  （currentBvid 更新）瞬间播放器页身份跳到当前页——组件销毁/重建都发生在看不见的页上。
- **竞态自愈**：requestedBvid 反映「pager 认定的应播页」而非 currentBvid 反向比较（后者在取流
  完成前是旧值，快速往返翻页会目标震荡）；取流完成后若发现用户已停在别的页，以页为准再发一次
  切换（openVideo 幂等）。
- **弹幕/历史/清晰度零改动**：全走 openVideo 既有链路；分 P/选集与滑动队列互不干扰。
- **返回语义**：pager 内返回键/手势 → `handleBack` → `exitFullscreen()` 形变回缩；退出后详情页
  停在最后刷到的视频（detail 已随切换更新），与 B 站官方一致。

## 四、挂账（后续优化，BiliPai 有而本轮未移植）

- **字节级预取**：BiliPai 的 `PlaybackMediaCache.prefetchRange`（视频头部 1.5MB + 音频 256KB 写
  SimpleCache 磁盘缓存，下一页近秒开）——bbspace 的 media3 DataSource 未接 SimpleCache，
  属播放内核级改造，单独立项。
- **playurl 预取**：翻页前预请求下一页 playurl（`resolvePortraitPlayUrlPreloadCount`：WiFi+开=3/
  WiFi=2/蜂窝=1）——bbspace 的取流封装在 StreamPlaybackSession 内部，需要先拆出可独立调用的
  playurl 入口。
- **首页推荐流补货**：接力流耗尽后的第三层数据源（getHomeVideos 分页）。
- **「只刷竖屏」开关**：过滤非竖屏视频（需详情接口查尺寸，并发受限）。
- dp 棘轮/守卫状态：本轮零新增 dp 字面量（SwipeCoverPage 全 token）；单测 122+20 全绿。

## 五、代码审查轮（同日追加）：可用性结论 + 修复 4 处 bug

对移植代码做了全路径推演（数据层 → ViewModel → pager → VideoScreen 接线 → 生命周期/进程重建
/手势/竞态），**结论：功能可用**。审查发现并已修复：

1. **锚点 target 不完整（高）**：原 `swipeEntryFromDetail` 构造 `Ugc(aid=0, cid=0, bvid)` 的
   裸 target，翻回页 0 时 `openVideo` 需额外一次 bvid 解析兜底。改为 `beginSwipeSession`
   直接取**栈顶 activeTarget**（完整 aid/cid/src），仅栈顶缺失时用 ids 兜底；
   该函数已删（连同其测试）。
2. **会话重试缺失 + 锚点漂移风险（高）**：快速滑进全屏时 detail 可能尚未返回，原
   `LaunchedEffect(fullOn)` 错过时机后会话永不开启；若简单加 detail 键重试，又会随刷视频
   的 detail 变化不断重置锚点（破坏"翻回页 0 = 进入时的视频"语义）。修：
   `LaunchedEffect(fullOn, videoState.detail)` + `swipeAnchor == null` 判据（detail 变化时
   已开启则跳过，锚点稳定），退出全屏 `clearSwipeSession()`，快速开退幂等。
3. **「无限刷」可能失效（中）**：`rememberPagerState` 会记住首次传入的 pageCount lambda，
   直接捕获 `pages` 的话队列追加后 pager 拿到的仍是旧页数。改为 `rememberUpdatedState(pages.size)`
   间接读。
4. **播完自动翻页缺失（体验，中）**：刷抖音的核心体验。补 `Player.Listener` 的
   `STATE_ENDED → animateScrollToPage(currentPage+1)`（最后一页不动；用户设单曲循环时
   STATE_ENDED 不发出，天然互斥；挂起调用经 `rememberCoroutineScope` 派发）。
5. **封面糊（低）**：全屏封面页误用 `CardCover`（小图 variant）→ `CardCoverLarge`。

### 审查确认无问题的点（推演过）

- **手势冲突**：pane 的 `playerPinchZoom` 在放大态消费单指拖动（子节点先于父 pager 收事件），
  非放大态放行 → 翻页/平移画面天然分区，无需 BiliPai 的 scale>1.01 禁滑显式处理；
  进度条为水平手势、控制条为 ModalBottomSheet（modal window 拦截下层），均不与垂直翻页冲突。
- **播放器唯一性与黑帧**：页身份由 `currentBvid`（取流完成才更新）驱动，组件销毁/重建
  都发生在用户看不见的页上；`PlayerViewTargetBinder` 的 ON_START/ON_STOP 绑定语义不变。
- **竞态自愈**：`requestedBvid` 反映「pager 认定的应播页」；取流完成后若用户已停在别的页，
  以页为准再发一次切换（openVideo 幂等）。
- **栈语义**：`openSwipeTarget` 替换栈顶，刷 20 个视频栈深仍为 1，返回键=退出详情；
  从详情页点相关推荐后进全屏（栈深 2）也正确（刷视频只动栈顶）。
- **弹幕/历史/清晰度/分P**：全走 `openVideo` 既有管线，零改动。
- **进程重建**：`swipeSessionActive` 为 saveable、VM 为新建（anchor null）→ 安全降级单 pane，
  且 LaunchedEffect 重跑自动重开会话。
- **merge 幂等**：`appendSwipeEntries` 空输入返回同引用，`MutableStateFlow` equals 短路，
  重复的 detail 到达不触发无效重组。

### 遗留（低优先，挂账）

- 取流失败无专门 UI（该页停留 loading，不重试不提示——回滑重进可恢复）。
- `normalizeSwipeTitle` 的括号截断对「同名系列视频」有低概率误杀去重（队列少一条，无崩溃）。
- 播完行为不可配置（BiliPai 有 STOP/REPEAT/CONTINUE 设置项）。
