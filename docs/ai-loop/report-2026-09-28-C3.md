## 任务 3（先修，独立性强）—— 过渡动画顽固 bug 根因与修复

### 链路梳理（AppNavHost / SeamlessVideoCardOpener / OplusViewSeamlessCompat / VideoDetailActivity）

打开视频详情共四条路径：
1. **卡片 + 无缝注册成功**：PixelCopy → `tryOpen` → `setSeamlessView` → `startActivity(intent, bundle)` → 系统 morph（正常，不受本次影响）；
2. **卡片 + 注册失败**：`tryOpen=false` → 回退 `onClick()` → `openVideoRoute`（版本支持 & 开关开）→ **`startActivity(intent)` 无 bundle** → 系统默认窗口动画；
3. **无锚点入口**（深链/搜索/历史/空间）：`openVideo`（bundle=null）→ 同路径 2 → 系统默认窗口动画；
4. **版本不支持/开关关**：覆盖层 `expand()`（Compose 内动画，与本次无关）。

退出路径：`finishWithHostState` / `finishWithDefaultTransition` → `finish()` → 窗口默认关闭动画。

### 根因

`Theme.Bbspace` **从未定义 `android:windowAnimationStyle`**。一切非无缝路径（路径 2/3 + 页内导航收起）
都落在系统默认窗口动画——ColorOS 16 默认即「打开=水平滑动、关闭=缩放」这种不对称组合。
用户观感（开=滑、退=缩）与此完全吻合；「顽固」是因为历轮都在修无缝调用点，而**兜底层从未有人管**——
无缝注册一旦失败或来自无锚点入口，观感立刻退化成系统默认。

### 修复

`app/src/main/res/anim/` 新增四件套（300ms，进入 decelerate / 退出 accelerate）：
- `window_open_enter`：fade 0→1 + scale 0.96→1.0；
- `window_open_exit` / `window_close_enter`：下层页面**静止**（钉死，不用系统默认滑出）；
- `window_close_exit`：fade 1→0 + scale 1.0→0.96（open_enter 的精确反向）。

挂载：`values/themes.xml` 与 `values-night/themes.xml` 的 `Theme.Bbspace` 上新增
`WindowAnimation.Bbspace`（parent=`android:style/Animation.Activity`）。**两个 Activity 共用该主题**，
无论框架从发起方还是接收方读样式，两侧都拿到同一套动画。

选型依据：96% 缩放 + 淡入淡出 = 仓库内 `ForegroundEnterBox` KDoc 注明的「ColorOS 设计语言」，
也与无缝 morph「从卡片尺度长出来」同族；开/关两方向严格对称。无缝 morph 正常接管时由系统覆盖窗口动画，互不干扰。

### 未动的部分（明确挂账）

- 预测性返回（manifest `enableOnBackInvokedCallback=true`）：Compose `BackHandler` 桥接为 non-predictive
  回调，手势不播系统预览、finish 后播本套 close 动画，行为自洽，不改。
- 详情页内点相关推荐走 `onNewIntent`（同 Activity），无窗口动画概念，维持现状。
