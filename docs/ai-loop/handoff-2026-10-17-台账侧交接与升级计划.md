## 5. 建议的升级计划书结构（给接手方/设计师直接可用）

**原则：用户要的是"看得见的变化"，每条计划必须写"用户会看到什么"（W75）。**

### 阶段 0（1~2 天）：复现与基线，**禁止改代码**

1. 定义"卡"：掉帧 / 输入延迟 / ANR 三选一并给出可复现步骤（哪个页面、什么操作、几次内必现）。
2. 用现有埋点出第一份读数：`adb logcat -s FirstFrame DecoderReuse PlaybackWatchdog ColdStart`，跑 5 次同操作取中位。
3. 复核 §1 盘面四行是否仍成立（HEAD / 81 处 / md5 / 源码冻结）。
4. 产出：一页"现状数字 + 三个最可疑点"，**没有这一页不准进阶段 1**。

### 阶段 1（UI，一次落一批，合一次门禁）

- 一批 = **U1 控制行三级层级 + U2 白度四档归并 + U3 气泡调序**（三者互不冲突，规格都已就绪）。
- 落批纪律：改 `VideoPlayerPane.kt` 行位置 ⇒ 同批更新 `GlassMountRegistryTest.kt:251/:259` 钉行号表（W27）；禁改点带当前值写进冻结令（W74）；跑批期间用看门狗（`chk01/watchdog.sh` 模板，每 20s 扫源码、排除 docs 与 build）。
- 用户可见目标：**底部控制条从"一排字"变成"有主次的三层"**；未播轨与已播轨在白底上仍可辨。

### 阶段 2（流畅度，按阶段 0 的读数排序）

- 先做读数指认的那一个，不做全清单。
- 每个改动必须带：埋点前后读数对比 + 一键回退 + 守卫断言。

### 阶段 3（收口）

- 全量门禁 + 当场快照 + `md5sum -c` + 装机复验；台账按三态收口。
